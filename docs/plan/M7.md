# M7 — Remote over SSH: detailed plan

Covers tasks M7-01 … M7-20 from [TASKS.md](../../TASKS.md).

## Context

The app runs well locally. The user wants the same experience when their agent sessions live on another machine: connect to a host over SSH and have everything work unchanged. That covers browsing, the transcript, search, live status, delete, export/import, handoff and resume commands. It reuses the system `ssh` and `~/.ssh/config`.

**Feasibility: yes.** Every provider, the index, the watcher, live detection (`/proc`, lock files), manage (gio trash, CLI exec, HMAC tokens) and handoff files are host-local by design. So they must run *on the remote*, next to the stores. This is the VS Code model:
- a small headless server runs on the remote over ssh stdio;
- the UI stays local.

What makes it cheap:
- `modernc.org/sqlite` is pure Go, so the core cross-compiles with `CGO_ENABLED=0` (only the desktop GUI needs CGO).
- `internal/app.Service` is already Wails-free.
- The frontend already talks through one hand-written `BackendAPI` (`frontend/src/lib/api.ts`).

Rejected: sshfs/sftp mounts. They break fsnotify, SQLite WAL, `/proc` live detection and CLI exec.

**Decisions (user):**
- One host at a time. A footer host chip switches the whole app between Local and one SSH host.
- Auth: keys/agent work silently; password, passphrase, 2FA and host-key prompts go through `SSH_ASKPASS` with an in-app dialog.
- Server delivery: bundled, auto-uploaded CGO-free server builds (linux/darwin × amd64/arm64).

## Architecture

```
Local desktop (Wails)                          Remote host
┌──────────────────────────────┐   system ssh   ┌─────────────────────────────────┐
│ Svelte UI ── api.ts (same)   │  (ControlMaster)│ agent-sessions-cli serve --stdio│
│ app.App facade (only bound)  │◄──JSON-RPC────►│ engine.Engine (same code as     │
│  ├─ active target: Local     │  NDJSON stdio  │  local: providers, index.db,    │
│  │   engine │ remote client  │                │  watcher, live, manage, handoff)│
│  ├─ dialogs, OpenURL, askpass│◄──raw channel─►│ transfer get/put (artifacts)    │
│  └─ connection manager       │                └─────────────────────────────────┘
└──────────────────────────────┘
```

- **`internal/engine`** (Wails-free) takes the `Service`, LRUs, actions, DTOs and the Wails-free half of export/import/handoff/manage/search from `internal/app`. It also takes the lifecycle previously in `App.OnStartup`/`Close`: index open, catalog load, Refresher, indexer, watcher, bootstrap, lazy `manage.Manager`.
  - Events go through an `Emitter` interface (`Emit(name, payload)`). This replaces `wruntime.EventsEmit` and the `ctx.Value("events")` check in `events.go`. The catalog bus (100 ms coalesce) moves too.
  - Start, Scan and Close are idempotent, and shutdown order is explicit.
  - After each watcher refresh, call `ApplyReport(refresher.Report())`. This fixes stale diagnostics from watcher events.
  - Type aliases stay in `internal/app` so existing callers and tests keep compiling.
- **`engine.Backend` interface.** It is context-first, uses JSON-able DTOs and covers every semantic binding: catalog, messages, blob, search, diagnostics, resume, handoff, export prepare, bundle open and handoff, manage settings, preview and delete, and the handoff cache.
  - Implementations: the local engine and `remote.Client`.
  - A reflection test asserts that the interface, the RPC dispatch table and the client all agree.
- **`app.App` stays the only Wails-bound type**, with the same method names, so `api.ts` changes only additively.
  - It holds the active target under an RWMutex: backend, artifact transport, generation and capabilities.
  - Local-only duties: dialogs, `OpenURL` (`open` on darwin, `xdg-open` on linux), `RevealSource` (unsupported when remote) and atomic writes of downloaded artifacts to local paths.
  - New bindings: `ListHosts`, `Connect(host)`, `Disconnect`, `ConnectionState`, `AskpassReply(id, answer)`.
  - New events: `connection:state` and `askpass:prompt`.
  - The local engine stays alive while a remote is active. Events are gated by source and generation, so stale remote notifications are dropped.
- **`internal/rpc`**: JSON-RPC 2.0 over newline-delimited JSON.
  - Startup: a nonce preface line (skips login-shell banners, with a 64 KiB scan cap and a timeout), then a mandatory `initialize` (protocol and app version, allowlisted env overrides such as `CLAUDE_CONFIG_DIR`, `CODEX_HOME` and `XDG_*`). Only then does the engine start and return resolved roots and capabilities.
  - Transport: concurrent handlers, mutex-protected writes, notifications for `catalog:changed` and `index:progress`, and `$/cancelRequest`.
  - Limits: a 64 MiB frame cap (no default `bufio.Scanner`) and a blob cap below it. Oversized payloads return `payload_too_large`.
  - Errors carry a stable code in `error.data.code`: `unknown_session`, `manage_disabled`, `preview_stale`, `session_live`, `unsupported`, `remote_busy`, `disconnected`, `cancelled`, `protocol_mismatch`, etc. The client rebuilds sentinels so `errors.Is` works.
  - The server logs only to stderr, and the client drains it continuously.
- **Server = `agent-sessions-cli serve --stdio`**, using the engine directly with no `internal/app` import. A dependency test asserts no Wails packages are linked.
  - It exits on stdin EOF and opens no listening ports.
  - An advisory lock on the remote cache ensures a second writer gets `remote_busy`.
  - Subcommands `transfer get|put <opaque-id>` stream artifacts from a per-connection staging dir (dir 0700, files 0600, sha256, size caps, expiry).
- **`internal/remote`** (desktop side):
  - `hosts.go`: best-effort alias list from `~/.ssh/config`. Follows `Include`, dedupes and skips wildcard and negated patterns. Manual alias entry is always allowed. `ssh -G` runs only for the chosen host and only needed fields are parsed.
  - `ssh.go`: argv-only (never a local shell) with these options:
    - `ControlMaster`, with a short private `ControlPath` using `%C` in `$XDG_RUNTIME_DIR/agent-sessions` or a 0700 temp dir;
    - `ControlPersist`;
    - `ServerAliveInterval` and `ServerAliveCountMax`;
    - no TTY;
    - `SSH_ASKPASS=<os.Executable()>`, `SSH_ASKPASS_REQUIRE=force`, a dummy `DISPLAY`.
    Rejects aliases starting with `-` or containing control characters. Remote command strings go through one POSIX-quoting function with adversarial table tests.
  - `probe.go`: one ssh call reports `uname -s/-m`, `$HOME` and installed server version.
    - Maps Linux/Darwin × x86_64/amd64/aarch64/arm64; anything else fails before upload.
    - Runs via login shell (`$SHELL -lc`, picking up PATH and agent env vars) behind the nonce preface. Direct-exec fallback exists.
  - `deploy.go`: installs to `~/.cache/agent-sessions/server/<version>-<sha8>/agent-sessions-cli`. Steps: stream gz, then `gzip -dc` to a temp file, chmod 700, verify sha256 when available, rename atomically, verify version handshake, and prune older versions.
  - `client.go` implements `Backend` over rpc. Per-call contexts derive from connection context, with timeouts by method class. On disconnect, calls fail with `ErrDisconnected`.
  - `transfer.go` handles artifact get/put over ControlMaster.
  - `locate.go` finds bundled servers: `/usr/lib/agent-sessions/remote/`, macOS `Contents/Resources/remote/`, dev `build/remote/`, then an env override. Never depends on cwd.
- **Askpass:**
  - Helper: `cmd/agent-sessions/main.go` checks `AGENT_SESSIONS_ASKPASS_SOCK` first. Connects to broker, authenticates with a per-connection token, sends prompt, prints answer and exits, without initializing GUI.
  - Broker: unix socket (0600) with same-UID peer check, size and time limits and queued prompts. Answers are never logged.
  - UI dialog shows exact prompt and host. Host keys are never auto-accepted; unknown prompts fall back to secure text input.
- **Connection semantics:**
  - Connect is transactional: Local stays active until remote has initialized.
  - Dropped remote does not fall back to Local. Host stays selected, stale overlay appears, mutations disabled, reconnect uses bounded backoff.
  - Mutations are never retried; if connection drops mid-call, reported as "outcome unknown" and app refreshes.
  - After reconnect, preview tokens and bundle IDs are stale. Dialogs close or re-preview.
- **Remote-aware behavior:**
  - Resume and handoff commands built remotely and wrapped as `ssh -t <alias> '<cmd>'` for local pasting. Handoff files live on remote.
  - Export: remote prepares artifact, downloaded, written to local save path.
  - Import: local file uploaded, remote opens it.
  - SaveHandoff writes locally.
  - Trash capability is probed. If unavailable, trash actions are disabled and never silently become permanent.
  - Manage `config.toml` is per-host on remote.
- **Frontend:**
  - `stores/connection.svelte.ts`.
  - Generation-based `reset()` in appState, manage, search, handoff, export and importer.
  - `agent-sessions:tree-collapsed` namespaced per target using hashed host ID; old key migrates to Local.
  - Host chip in footer status opens host picker menu. Disconnected banner, host-aware delete dialogs, AskpassDialog.
  - `MockBackendAPI` gains mock hosts.
- **Version:**
  - `internal/version` package stamped via `-ldflags -X` from `wails.json` `productVersion`. Replaces `appVersion` in `internal/app/export.go`.
