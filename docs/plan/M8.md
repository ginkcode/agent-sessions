# M8 — Windows support: detailed plan

Covers tasks M8-01 … M8-09 from [TASKS.md](../../TASKS.md).

## Context

The app runs on Linux and macOS. Windows support is feasible because the core
was kept platform-clean:

- **Cross-compile check (2026-10-01):** `GOOS=windows GOARCH=amd64` builds both
  the headless CLI and the desktop app cleanly, with one missing piece:
  `internal/paths` has no Windows `FromEnv` (`paths_linux.go`/`paths_darwin.go`
  only). A stand-in for that file makes `go vet ./...` clean. Nothing has been
  run on a real Windows machine.
- `modernc.org/sqlite` is pure Go (no CGO); Wails v2 supports Windows.

**Decision (user): ship in two steps.**

1. **M8-01…M8-07 — local-first Windows support.** Everything local works:
   browsing, transcripts, search, export/import, handoff, manage (Recycle
   Bin), packaging. The SSH host picker stays hidden on Windows.
2. **M8-08…M8-09 — remote over SSH, later.** It is blocked on askpass security
   and works differently without ControlMaster. Not started until the local
   port is proven on a real machine.

## Easy: paths, UI glue, local features

### M8-01 `paths_windows.go`

Roots on Windows:

| Root | Location |
|---|---|
| Claude | `%CLAUDE_CONFIG_DIR%` or `%USERPROFILE%\.claude` |
| Codex | `%CODEX_HOME%` or `%USERPROFILE%\.codex` |
| OpenCode | `%XDG_DATA_HOME%\opencode` or `%USERPROFILE%\.local\share\opencode` |
| App data | `%LOCALAPPDATA%\agent-sessions` |
| Cache | `%LOCALAPPDATA%\agent-sessions\cache` |
| Config | `%APPDATA%\agent-sessions` |

Follow the existing `FromEnv(getenv, home)` contract; absolute-override env
vars keep working. A `wails.json`/NSIS build will verify the app boots.

**Done (2026-10-03), checked on a real Windows 11 machine from WSL:**

- OpenCode resolves its data dir with `xdg-basedir` on every OS, so it lives
  under the profile's `.local\share`, not `%APPDATA%`. Confirmed on disk.
  Unset or relative `LOCALAPPDATA`/`APPDATA` fall back to
  `%USERPROFILE%\AppData\Local` and `\Roaming`.
- **SQLite DSNs were broken on Windows.** `url.URL{Scheme: "file", Path: "C:/…"}`
  renders `file://C:/…`, which SQLite rejects as `invalid uri authority`.
  It broke the app's own index and every OpenCode/Codex database open. All four
  builders now use `pathutil.SQLiteURI`, which renders `file:///C:/…`.
- The Windows CLI `detect` and `scan` find all three agents' real sessions.
- Workflow: cross-compile in WSL, then run the `.exe` (or a
  `go test -c` binary) through WSL interop. Pass env vars with `WSLENV`.
- The user confirmed production GUI startup and session listing on Windows
  (2026-10-04). The installer and broader interaction QA remain open.

**Found by running package tests on Windows (all fixed 2026-10-03):**

- Codex records CWDs with the `\\?\` long-path prefix
  (`\\?\D:\Workspaces\x`); grouping must strip it. → fixed in M8-03.
- Unix-path fixtures (`/custom/root`, absolute `/home/dev` CWDs) fail
  `filepath.IsAbs` on Windows; error checks compare `%q`-escaped paths.
  → fixed in M8-03 and the test fixtures.
- Open files cannot be removed on Windows. Three real bugs came from this:
  - `transfer get --remove` deleted the artifact while it was still open, so
    the delete silently failed. It now closes the file first.
  - Index rebuild wiped the DB while another process's reader held it open.
    Rebuild now resets the schema in place (see "Index rebuild" below).
  - Test fixtures leaked open handles (OpenCode fixture DBs, app index
    handles on `TempDir` cleanup).
- Mode-bit assertions (`0600`/`0700`, unreadable files) don't apply; the
  per-user profile ACL protects `%LOCALAPPDATA%`. Tests skip them via
  `internal/testutil/platform`.
- Symlink tests need Developer Mode or admin. They skip when `os.Symlink`
  fails with `ERROR_PRIVILEGE_NOT_HELD`.
- Tests that read `testdata` must run with the package dir as the working
  directory, which `go test` already does.

**Index rebuild with open readers (done 2026-10-03).** Windows cannot delete
a file another process holds open, and modernc's VFS doesn't open with
`FILE_SHARE_DELETE`. `Rebuild` now drops and recreates the schema in one
transaction on the writer's own handle, so the file is never replaced.
Readers keep their WAL snapshot until it ends, then see the empty schema.
`Open` resets a newer-version or corrupt schema the same way. It deletes the
file only if that reset fails, and never after cancellation. A deeply damaged
file that another process holds open still falls back to the in-memory index.
The reset doesn't shrink the file (no VACUUM).

### M8-02 Reveal and OpenURL

`internal/app/app.go` runs `open` (darwin) or `xdg-open` (everything else).
Windows needs `explorer /select,<file>` for Reveal and
`rundll32 url.dll,FileProtocolHandler <url>` (or `explorer <url>`) for
OpenURL. Extract a `desktopOpen` helper with a per-GOOS implementation.
Remote sessions already hide Reveal (e5026b1), so this is local-only.

**Code done (2026-10-03).** `desktopOpen` in `internal/app/app.go` picks the
command per GOOS. On Windows, Reveal runs `explorer <dir>`: the backend
returns the source directory, as on the other platforms, so there's no file
to `/select`. OpenURL runs `rundll32 url.dll,FileProtocolHandler <url>`, which
skips cmd.exe and its `&`/`^` parsing. The child is reaped in the background
and its exit status ignored (Explorer exits 1 on success). A real-machine
click-through is part of M8-10.

### M8-03 Windows path handling

Sessions recorded on Windows have drive letters (`C:\`), backslashes, and
case-insensitive comparisons. Audit and test with real Windows fixtures:

- `internal/group` directory keys, sorting, "fold into repo" labels
  (`directoryKey`, `pathLabel`).
- `internal/pathutil.NormalizeDir` and the git resolver.
- Claude's project-folder encoding (dots for separators) when cwd is a
  Windows path.
- `frontend/src/lib/tree.ts` and the path filter — the frontend receives
  remote/local paths as data and must render both styles.
- The export default file name (`ExportFileName`) already sanitizes `\ :` —
  add fixtures.

**Done (2026-10-03).** Session paths are data from the machine that recorded
them, so their style comes from the path itself, not from the host OS:

- `pathutil` `IsWindows`/`IsAbs`/`Clean`/`Rel`/`Separator`. Windows paths
  lose `\\?\` (and `\\?\UNC\`), use backslashes, and get an upper-case drive.
  POSIX paths stay POSIX on a Windows host. `NormalizeDir`, `Exists` and the
  git resolver never probe a path in the other OS's style. `filepath` stays
  for files opened on this machine, including restore targets.
- Grouping keys fold case for Windows paths (shown with their recorded
  case). The `~` label works for Windows homes and never crosses styles.
- Claude, Codex and OpenCode normalize Windows CWDs on any host. Their
  checkpoint versions were bumped, so cached raw paths get rescanned.
- Claude tool-results references with `\tool-results\` are recognized.
- Search `Dir` filters match child directories. Before, the LIKE pattern
  lacked its `%`, so they never did. POSIX paths match case-sensitively
  (GLOB); Windows paths match case-insensitively (ASCII only, like SQLite).
- Handoff `--cwd` checks use the path's own style. Tool and patch paths keep
  their style. The handoff save dialog offers a flat file name for subagent
  IDs.
- Claude project-folder encoding already maps `C:\x` to `C--x`; fixtures
  added. Export file-name fixtures cover drive roots, UNC and `\\?\`.
- Frontend: `tree.ts` and the filter treat paths as opaque strings. Tests
  pin Windows/UNC keys. The sidebar filter is a literal substring, so `/`
  doesn't match a stored `\`. Left as is.
- Known limit: grouping folds Unicode case, SQLite only ASCII. A group with
  non-ASCII letters differing in case may find fewer sessions in search.

### M8-04 Live-session detection

`internal/provider/claude/live_other.go` reads `/proc`, which does not exist
on Windows; sessions simply never show as live. Acceptable for step 1; a
`live_windows.go` using the Windows process APIs is a follow-up. Keep the
fallback compiling.

**Deletion guard added (2026-10-04).** The LIVE badge fallback must not serve
as proof that a session can be deleted. Management now takes a Windows
Toolhelp process snapshot and conservatively blocks Claude, Codex and
OpenCode deletion while matching agent executables run. Native executable
names are case-insensitive; version/platform-suffixed names also match.
Arguments are not inspected, so server/daemon processes are not exempted.
Node.js, Bun and Deno hosts make liveness unknown and block deletion—even an
unrelated runtime can do so. Claude Desktop is also `Claude.exe` and blocks
Claude deletion while running. This is deliberate: it can host Claude Code
sessions and names cannot tell the two apart. Snapshot errors also fail closed. The process
guard is rechecked before each recycled path or provider delete. The existing
ten-minute inactivity check, Claude provider/child checks, path validation
and preview tokens remain. No Windows LIVE badge is claimed.

### M8-05 Trash → Recycle Bin

The original Windows stub left Claude without a trash transport. Claude
has no permanent-delete fallback. Codex and OpenCode are separate permanent
provider-specific operations, not recyclable session files, and require
`allowPermanentDelete`. OpenCode's shared database must never be recycled.

**Implementation in progress (2026-10-04).** Use Windows 10/11
`IFileOperation` rather than legacy `SHFileOperation`/`FOF_ALLOWUNDO`:
explicit recycle-on-delete flags, a progress sink that vetoes nonrecycle
operations, checked per-item recycling evidence, cancellation and native
errors. No fallback to permanent deletion. The transport accepts only
unambiguous local fixed-volume paths; unsupported paths/volumes fail closed.
The native safety gate remains closed until synthetic smoke tests confirm
both successful recycling and veto of a permanent operation.

**Native smoke results (2026-10-04, Windows 11, NTFS `C:`).** The opt-in
`TestWindowsRecycleNativeSmoke` (`AGENT_SESSIONS_RECYCLE_SMOKE=1`) uses only
files it creates in a private temp dir. It passes:

- A Unicode-named file and a directory with a `subagents\` child are each
  recycled in one pre/post callback pair: `PreDeleteItem` flags `0x280`
  (includes `TSF_DELETE_RECYCLE_IF_POSSIBLE`) and `PostDeleteItem` with a
  Bin item. The Shell reports `COPYENGINE_S_DONT_PROCESS_CHILDREN`
  (`0x00270008`), not `S_OK`, for a recycled item. Only those two codes are
  accepted, and only with a Bin item. `S_FALSE` and other skip codes are
  refused. The first run refused `0x00270008` and reported outcome unknown,
  as intended, after the file had already been recycled.
- With the recycle flags removed (test-only wrapper), the real Shell's
  preflight lacks the recycle flag and is vetoed. The fixture is unchanged.

**Gate still closed.** `windowsRecycleSafetyValidated` stays `false`, so
Windows Claude deletion is still blocked as "trash is not supported". The
docs say `TSF_DELETE_RECYCLE_IF_POSSIBLE` means "if possible". They do not
say whether the preflight drops the flag or the Shell instead asks to delete
permanently (`FOF_WANTNUKEWARNING`, no `FOF_NOCONFIRMATION`) when:

- the drive's Bin is disabled ("Don't move files to the Recycle Bin"),
- the Bin is over quota, or
- the item is larger than the Bin.

Testing these needs changed Recycle Bin settings or a disposable machine,
not the user's own settings. Open the gate only after those cases fail
closed or show the nuke confirmation on such a machine.

The delete preview carries an optional backend `trashLabel`, so Windows
operations say **Recycle Bin** and older servers fall back to **Trash**.
All-blocked previews show a neutral disabled **Delete** button with grouped
reasons, not a misleading **Move to Trash** action. Codex/OpenCode and mixed
permanent actions retain their irreversible warnings. Unverified shell
outcomes are listed separately from files known to remain; they never cause
automatic retry or catalog forgetting.

### M8-06 PowerShell command quoting

Resume and handoff commands are built as
`cd '<dir>' && claude '<prompt>'` (`FormatResumeCommand`,
`handoff.shellEscape`). In PowerShell single quotes work, but `&&` needs
PS7+ and `cd` with quoted paths behaves differently in cmd.exe. Decide the
target shell (PowerShell 5 is preinstalled), write a `shellEscape` for it,
and test the commands by pasting them on a real Windows machine. The launch
command stays one line pointing at the handoff file.

## Hard: remote over SSH on Windows

### M8-08 Askpass security on Windows

The askpass bridge uses a Unix socket whose peer-UID check
(`peeruid_linux.go`) and private-dir check (`privatedir_unix.go`) are skipped
on non-Unix builds (`*_other.go` return nil). On Windows the password channel
would be unauthenticated — this violates the handoff rule that askpass
answers are never exposed. Required design:

- Named pipe (`\\.\pipe\agent-sessions-askpass-<pid>`) restricted to the
  current user via a security descriptor (DACL), equivalent to the Unix
  0600 + peer-UID checks. `golang.org/x/sys/windows` has the APIs.
- OpenSSH-for-Windows honors `SSH_ASKPASS`/`SSH_ASKPASS_REQUIRE` the same
  way; verify with the local sshd harness equivalent.
- Re-enable the "no listening sockets" CI assertion on Windows once the
  pipe is scoped per-user.

### M8-09 No ControlMaster

Windows OpenSSH does not support connection multiplexing (ControlMaster/
ControlPath/ControlPersist), but it does support a long-lived SSH process.

Chosen design: **retain the existing persistent stdio JSON-RPC session**
(`ssh host … serve --stdio` in `internal/remote/session.go`). Scan/Refresh,
listing, transcript reads, search and delete share that connection. Keep
its existing heartbeat and reconnect handling; no loopback listener or
`ssh -L` forward is needed.

- Disable ControlMaster/ControlPath/ControlPersist options and skip master
  shutdown (`ssh -O exit`) on Windows.
- Initial probing, deployment and artifact transfers currently run separate
  SSH commands. Without ControlMaster, these establish separate connections;
  normal RPC actions do not. For the first Windows remote release, require
  working noninteractive keys/agent authentication to avoid repeated prompts.
- Use a successful noninteractive probe (`BatchMode=yes`) as the gate, not
  `ssh -G` configuration alone or the presence of an agent service. Keep the
  host picker available to explain prerequisites, but do not activate a
  remote backend until the probe succeeds.
- Later, if password authentication is needed, move transfers into bounded,
  cancellable RPC chunks and evaluate a single-connection probe/deploy/serve
  bootstrap. This is deferred, not a prerequisite for M8-09. M8-08 remains
  required for a secure Windows askpass bridge.
- Git-for-Windows/MSYS/Cygwin ssh is not required and is not a silent fallback.
  An explicit executable override can be evaluated later.

Client and spawn details:

- **Binary:** the Windows-native client (normally under
  `%WINDIR%\System32\OpenSSH\ssh.exe`) is the target. OpenSSH is available
  as a Windows optional feature; do not assume it is installed on every
  Windows 10/11 machine. Discover the executable, prefer the native path over
  a generic `PATH` lookup so Git-for-Windows/MSYS ssh does not shadow it, and
  log the chosen binary. If absent, disable remote connection and show
  optional-feature installation guidance.
- **Console window:** suppress console windows on SSH/helper spawns from
  Wails with Windows-specific `SysProcAttr` (`HideWindow`/`CREATE_NO_WINDOW`,
  tested against the actual helpers). Cover both the persistent session and
  separate setup/transfer commands.
- **Agent:** the Windows `ssh-agent` service is disabled by default and
  listens on `\\.\pipe\openssh-ssh-agent`. Document enabling and starting
  the service from an elevated PowerShell, then adding a key with `ssh-add`.
  Service status is diagnostic only: an unencrypted key or a compatible
  third-party agent can work without it. Agent interoperability must be
  verified with the selected native client; a Git Bash/Pageant setup is not
  automatically compatible.

Verification for M8-09 on a real Windows client:

- Connect from a Start-menu launch (no inherited Git Bash environment).
- Repeat Refresh, transcript reads, search and delete over the same running
  SSH/RPC session; verify no per-action reconnect or console flash.
- Exercise separate deployment and upload/download commands with keys/agent.
- Drop the transport and verify reconnect, then disconnect and verify the
  session exits without a ControlMaster shutdown command.
- Missing client, unusable keys and disabled agent produce actionable
  guidance, not password prompts or a silently selected alternate client.
