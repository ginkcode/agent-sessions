# M2 — Index, search, live updates: detailed plan

Covers M2-01 … M2-12 in [TASKS.md](../../TASKS.md), ≈ 36 h including tests.
M0's [shared contracts](M0.md) are authoritative: `model.SessionRef`,
`SessionMeta`, `Transcript`, `provider.Provider.Scan(ctx, prev ScanState)
(ScanResult, error)`, `ScanResult{Changed, Removed, State, Diag}`,
`SourceState{Size, ModTimeNs, Offset, Checkpoint}`, `ScanState{Sources,
Cursor}`, `LiveDetector`, and `jsonl.Reader`. Do **not** silently change them.
M1 supplies `internal/scan`'s in-memory `Catalog` (`Apply(result)`, `All()`,
`Get(ref)`, `Children(ref)`), `internal/group`, the OpenCode and Codex
providers, and the Wails v2 `internal/app.SessionService` with paged
`GetMessages`, `GetBlob`, list and metadata methods. The Svelte 5 frontend
accesses bindings/events only through `frontend/src/lib/api.ts` (including
its mock backend). Names below for new methods are proposed additions, not
rewrites of those M1 contracts.

---

## Cross-cutting invariants and integration

- **Tool stores remain read-only.** All SQL writes are to our private cache.
  Never open credential files (`.credentials.json`, `auth.json`) or OpenCode
  credential/account tables. No network, telemetry, or remote resources.
- The cache is an acceleration layer, not the source of truth. A missing,
  corrupt, incompatible or deleted cache triggers a full background rebuild;
  it must never break browsing. Diagnostics remain available in memory.
- The **catalog and cache represent the same committed provider scan**: write
  `Changed`, `Removed`, and the complete new `ScanState` in **one transaction
  per provider**, then `Catalog.Apply(result)` and notify the UI. If a write
  fails, do not advance the catalog/state; retry from the old state. Serialize
  scans/writes for the same provider; different providers may run in parallel.
- `Live`/`LiveStatus` are volatile. Restore cached metadata with these cleared;
  the live poll alone owns them. Neither transient liveness nor indexing
  progress increments the transcript FTS revision.
- A ref is always `(agent,id)`, never bare id. For a child session, retain
  `ParentID`, `ParentToolCallID`, and the full `Meta` JSON for M1 grouping.
  `messageIndex` is the **zero-based index in `Transcript.Messages` and
  `GetMessages(ref, offset, limit)`**, including normally hidden meta/system
  rows; do not use `Counts.Total()`, source line number, or OpenCode `seq`.
- On startup, register UI event listeners **before** requesting the first
  snapshot; `ListGroups`/`ListSessions` must always read the current catalog.
  An event is an invalidation hint, not an irreplaceable data stream.
- Run M0/M1 tests plus `go test -race ./...`, `make lint test`, and
  `svelte-check` for relevant changes. Performance targets are measured on a
  real ≈300 MB history, never asserted with machine-dependent CI timings.

## M2-01 Cache DB, schema and migrations (3 h)

**Files:** `internal/index/db.go`, `internal/index/migrations.go`,
`internal/index/migrations/001_initial.sql`, `internal/index/db_test.go`;
`internal/paths` only as an existing `Roots.Cache` consumer.

```go
// index owns only our disposable database; no provider imports index.
type DB struct { /* *sql.DB, path, single-writer coordination */ }
func Open(ctx context.Context, cacheDir string) (*DB, error)
func (d *DB) Close() error
func (d *DB) LoadCatalog(ctx context.Context) ([]model.SessionMeta, error)
func (d *DB) LoadState(ctx context.Context, agent model.AgentID) (provider.ScanState, error)
func (d *DB) CommitScan(ctx context.Context, agent model.AgentID,
    result provider.ScanResult) error
```

**Schema, migration 001** (embed `migrations/*.sql` with `//go:embed`, execute
in version order; `ref` is `SessionRef.Key()`, while `agent` and `id` remain
separate for easy joins/filters):

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version INTEGER PRIMARY KEY,
    applied_at INTEGER NOT NULL                    -- Unix milliseconds UTC
);
CREATE TABLE IF NOT EXISTS sessions (
    ref TEXT PRIMARY KEY NOT NULL,
    agent TEXT NOT NULL,
    id TEXT NOT NULL,
    parent_id TEXT NOT NULL DEFAULT '',
    source_path TEXT NOT NULL,
    meta_json TEXT NOT NULL,                        -- complete SessionMeta JSON
    title TEXT NOT NULL DEFAULT '',
    cwd TEXT NOT NULL DEFAULT '',
    repo_root TEXT NOT NULL DEFAULT '',
    created_at INTEGER NOT NULL DEFAULT 0,         -- Unix milliseconds UTC
    updated_at INTEGER NOT NULL DEFAULT 0,
    msg_total INTEGER NOT NULL DEFAULT 0,          -- Counts.Total()
    tokens INTEGER NOT NULL DEFAULT 0,             -- sum of TokenUsage fields
    cost REAL NOT NULL DEFAULT 0,
    archived INTEGER NOT NULL DEFAULT 0 CHECK (archived IN (0,1)),
    model TEXT NOT NULL DEFAULT '',
    fts_revision INTEGER NOT NULL DEFAULT 0,       -- bump on source/metadata change
    UNIQUE(agent, id)
);
CREATE INDEX IF NOT EXISTS sessions_agent_updated
    ON sessions(agent, updated_at DESC);
CREATE INDEX IF NOT EXISTS sessions_cwd_updated
    ON sessions(cwd, updated_at DESC);
CREATE INDEX IF NOT EXISTS sessions_repo_updated
    ON sessions(repo_root, updated_at DESC);
CREATE INDEX IF NOT EXISTS sessions_created ON sessions(created_at DESC);
CREATE INDEX IF NOT EXISTS sessions_parent ON sessions(agent, parent_id);
CREATE INDEX IF NOT EXISTS sessions_filter
    ON sessions(archived, model, msg_total DESC);
CREATE INDEX IF NOT EXISTS sessions_cost ON sessions(cost DESC);
CREATE INDEX IF NOT EXISTS sessions_tokens ON sessions(tokens DESC);
CREATE TABLE IF NOT EXISTS provider_state (
    agent TEXT PRIMARY KEY NOT NULL,
    state_json TEXT NOT NULL                         -- full ScanState JSON
);
-- Durable, resumable index queue; stale revisions are not allowed to publish.
CREATE TABLE IF NOT EXISTS fts_jobs (
    ref TEXT PRIMARY KEY NOT NULL REFERENCES sessions(ref) ON DELETE CASCADE,
    revision INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    attempts INTEGER NOT NULL DEFAULT 0,
    last_error TEXT NOT NULL DEFAULT ''
);
-- One title row at message_index=-1; one text row per indexed message.
-- This ordinary table is the external content and maps rowid -> ref/index.
CREATE TABLE IF NOT EXISTS fts_docs (
    rowid INTEGER PRIMARY KEY,
    ref TEXT NOT NULL REFERENCES sessions(ref) ON DELETE CASCADE,
    message_index INTEGER NOT NULL,
    body TEXT NOT NULL,
    UNIQUE(ref, message_index)
);
CREATE INDEX IF NOT EXISTS fts_docs_ref ON fts_docs(ref);
CREATE VIRTUAL TABLE IF NOT EXISTS fts_messages USING fts5(
    body, content='fts_docs', content_rowid='rowid',
    tokenize='unicode61 remove_diacritics 2', prefix='2 3 4'
);
-- External-content FTS requires delete commands with the *old* text.
CREATE TRIGGER IF NOT EXISTS fts_docs_ai AFTER INSERT ON fts_docs BEGIN
    INSERT INTO fts_messages(rowid,body) VALUES (new.rowid,new.body);
END;
CREATE TRIGGER IF NOT EXISTS fts_docs_ad AFTER DELETE ON fts_docs BEGIN
    INSERT INTO fts_messages(fts_messages,rowid,body)
        VALUES('delete',old.rowid,old.body);
END;
CREATE TRIGGER IF NOT EXISTS fts_docs_au AFTER UPDATE ON fts_docs BEGIN
    INSERT INTO fts_messages(fts_messages,rowid,body)
        VALUES('delete',old.rowid,old.body);
    INSERT INTO fts_messages(rowid,body) VALUES(new.rowid,new.body);
END;
```

**Why external-content FTS:** `fts_docs` supplies stable message-index mapping
and the text that FTS5 needs for `snippet()`; FTS5 otherwise stores its own
second copy of all text, or contentless FTS cannot produce snippets without a
second lookup. Triggers keep the index synchronized with row deletes and
cascades. `fts_docs` is derived/private; full transcripts remain with tools.
Title has `message_index=-1`; a title hit opens the session at its first
visible message. Avoid an FTS row for an empty message or meta-only content.

**Steps**
1. Resolve `paths.Default().Cache`; `os.MkdirAll(dir, 0700)`, reject a cache
   symlink, enforce `0700` on an existing directory and `0600` on an existing
   regular DB. Create the DB with an explicit `os.OpenFile(path,
   os.O_RDWR|os.O_CREATE, 0600)` before `sql.Open`, with process umask `0077`
   around creation where appropriate so SQLite-created `-wal`/`-shm` files
   are private too. Do not change any tool store's permissions. Handle
   concurrent app instances via SQLite busy timeout, not lock-file deletion.
2. Use `modernc.org/sqlite` (pure Go). Its generated Linux build includes
   `-DSQLITE_ENABLE_FTS5` (verified in v1.56.0's generated
   `lib/sqlite_linux_amd64.go`; [module docs](https://pkg.go.dev/modernc.org/sqlite),
   [FTS5 reference](https://sqlite.org/fts5.html)). Still add an in-memory
   smoke test that creates an FTS5 virtual table; no loadable extension or
   cgo build tag is required.
3. Example DSN: `file:<URL-escaped-absolute-path>?_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)&_pragma=foreign_keys(ON)`.
   Build with `net/url` so spaces and `#` in paths do not break it.
   `_pragma` is applied **on every connection** by modernc's driver; also set
   `SetMaxOpenConns(2)` (one short reader plus a serialized writer) and
   `SetMaxIdleConns(2)`. Verify `PRAGMA journal_mode=WAL`,
   `foreign_keys=1`, `busy_timeout=5000` and `0600` DB/sidecars in tests.
4. `schema_migrations` is the authoritative version: a transaction creates
   it and runs each unapplied embedded SQL file once, then inserts its
   version. SQL uses `IF NOT EXISTS` so replay after interruption is safe.
   If recorded version is newer than bundled migrations, or schema is
   malformed/failed integrity check, close and rebuild the **private** DB,
   preserving no cache data. Do not silently run old SQL against newer data;
   log a diagnostic. Never delete the SQLite WAL while the DB is open.
5. `CommitScan`: UPSERT all `Changed` (encode full meta with live flags
   cleared), DELETE `Removed` by `(agent,id)`, and replace the agent's complete
   `ScanState` JSON in `provider_state`, all in one transaction. Increment
   `fts_revision` only for a real changed ref; UPSERT `fts_jobs` with that
   revision. Deletions cascade through `fts_docs`/jobs and their FTS triggers.
   Existing FTS rows stay searchable until replacement, except deleted refs;
   queries join `sessions` and require no stale revision once M2-04 adds it.

**Tests:** migration on empty DB, reopen idempotence, newer-version rebuild,
rollback on injected write error (including unchanged provider state), CASCADE
FTS delete, perms and `PRAGMA`s, clear live flags in round trip, Unicode/path
DSN, and compiled FTS5 smoke test. Use temp dirs; do not touch real cache.

**Done when:** A fresh/reopened cache restores all metadata and provider
states, a failed transaction restores neither, and the private files have
safe permissions.

## M2-02 Incremental indexing and cache-first startup (4 h)

**Files:** `internal/index/refresh.go`, `internal/scan` integration,
`internal/app` startup wiring, `internal/index/refresh_test.go`.

```go
// One Refresh invocation per provider at a time; scan.Provider remains M0.
func (r *Refresher) Refresh(ctx context.Context, p provider.Provider) (
    changed []model.SessionRef, removed []model.SessionRef, err error)
func (r *Refresher) Bootstrap(ctx context.Context) error
```

**Steps**
1. During startup, `index.Open` and `LoadCatalog` (bounded metadata read
   only), populate M1 `Catalog` with those metas; notify the initial UI
   snapshot immediately. Start `Bootstrap` scans asynchronously, not in
   `OnStartup`'s paint-critical path. Subscribe to events before taking the
   snapshot so no invalidation is lost. A damaged cache shows an empty/loading
   snapshot then rebuilds; a missing provider root is diagnosed rather than
   causing a false global failure.
2. For each detected provider, load its **persisted** `provider_state` and
   pass it unmodified to `p.Scan(ctx, prev)`. M0 Claude and M1 Codex compare
   `(size,mtime)` per absolute path; unchanged sources yield no change.
   On append, resume from `SourceState.Offset` and its provider-private
   `Checkpoint` (aggregated counts/title/tokens, last assistant id); do not
   mistake a partial trailing JSONL line for committed data: M0 `jsonl.Reader`
   retains its start offset. File shrink, lost/malformed checkpoint, offset
   beyond size, source replacement/rotation (inode if tracked by provider,
   otherwise a changed file with same size/mtime detected by a periodic
   verification), or timestamp regression requires full rescan; a vanished
   source is `Removed`. Codex `threads` data and JSONL must agree on the
   returned state. Watch event paths are advisory, never persisted as truth.
3. `DB.CommitScan` first; then `Catalog.Apply(result)`; then emit the M2-08
   change event. If no changes but the scan state advanced, commit state
   without a UI event. If cache commit fails, leave the old state/catalog and
   retry. Keep provider root detection and provider errors per-agent so other
   providers remain usable. Graceful shutdown cancels scans and closes DB
   after worker completion.
4. Measure timestamped `index.Open → LoadCatalog → first frontend snapshot`
   separate from background scan and FTS build. Target < 300 ms first paint
   for ≈300 MB transcripts; querying only `sessions` (not FTS or `Load`) is
   critical. Capture timings for warm/cold fixtures; do not claim cold FTS
   indexing is within the <5 s metadata-scan target.

**Edge cases:** ignore a stale asynchronous scan after `ClearCache` using a
refresher generation; a source that disappears between discovery/stat/read
produces a warning and a later reconciliation rather than deleting a valid
row on a transient permission error. If a scan was interrupted before commit,
replay its old checkpoint safely. Multi-root paths remain keys in
`ScanState.Sources`, not just the session id.

**Tests:** fake providers recording `prev` and returning diffs; cache restart
restores meta/state; unchanged scan does no `Load`; append and partial-last-
line fixture increments counts exactly once; shrink/replace/full rescan;
failed commit/cancel leaves state unchanged; delayed provider doesn't block
cached listing or another provider.

**Done when:** cached sessions render before scans complete, warm first paint
is measured < 300 ms, and append/shrink/delete produce correct counts.

## M2-03 OpenCode incremental refresh (2 h)

**Files:** `internal/provider/opencode/scan.go` (M1 code),
`internal/provider/opencode/scan_test.go`; no index-specific SQL in provider.

```go
// ScanState.Cursor = decimal max(time_updated) in Unix milliseconds.
// SourceState.Checkpoint at the absolute DB path holds the private id
// inventory for deletion reconciliation (JSON, not a new shared field).
```

**Steps**
1. For v2 query `session_v2 WHERE time_updated >= ? ORDER BY
   time_updated,id` on noninitial scans; `>=` deliberately rechecks a
   same-millisecond boundary. Only fetch full metadata and message-count SQL
   for those rows, deduping by id against v1/legacy per M1. Advance `Cursor`
   to the maximum observed timestamp **only after** all reads succeed.
   Initial/cursor-corrupt DB/generation change performs full metadata scan.
2. At startup and every 60 s, cheaply query **all ids**, e.g.
   `SELECT id FROM session_v2`, and compare to the previous inventory in
   `SourceState.Checkpoint` for the absolute DB path. Include v1 and legacy
   id sets where present: a v2 deletion may expose a v1 row rather than
   removing the canonical session. Return `Removed` only if gone from all
   generations; for changed ownership return `Changed` with fallback meta.
   Reconcile archived/renamed legacy files on the same sweep. Checkpoint
   the **new** sorted canonical id set along with `Cursor` in `ScanResult.State`.
3. On a WAL watcher event, requery changed rows and inventory as scheduled;
   coalesce repeated writes. Do not scan message bodies or touch credential
   tables. DB reads use M1's `mode=ro`, short transactions and busy timeout.

**Edge cases:** `time_updated` is milliseconds; never compare to Go
nanoseconds. Same timestamp, DB replaced/rolled back, archive flag updates,
legacy-only ids, v1→v2 upgrade, and a deleted id with a v1 fallback. If a
format stops updating `time_updated` for message writes, report a diagnostic
and periodically recheck recent sessions rather than claiming exactness.

**Tests:** synthetic read-only fixture DB: query count proves unchanged rows
aren't re-read; equal-timestamp update, cursor rollback, v2 deletion,
v1 fallback and empty DB; only one DB-source checkpoint advances with diff.

**Done when:** steady refresh reads changed metadata only and a deleted id
vanishes within one reconciliation interval.

## M2-04 Background FTS5 indexing pipeline (4 h)

**Files:** `internal/index/fts.go`, `internal/index/worker.go`,
`internal/index/fts_test.go`, `internal/app` index-progress event bridge.

```go
type FTSProgress struct {
    Done int `json:"done"`
    Pending int `json:"pending"`
    Failed int `json:"failed"`
    Running bool `json:"running"`
}
func (d *DB) IndexPending(ctx context.Context, providers provider.Set,
    emit func(FTSProgress)) error
```

**Steps**
1. `CommitScan` enqueues changed refs in `fts_jobs` at their new
   `fts_revision`, ordered by `updated_at DESC`; do not call `Load` in the
   metadata scan or block first paint. A single low-priority worker reads
   jobs in newest-first order, yielding to interactive `GetMessages` and
   respecting cancellation. Concurrency **1** initially (bounded at 2
   after measurement) avoids thrashing the 300 MB JSONL history / 248 MB
   OpenCode DB. A worker restart simply resumes persisted jobs; retry
   transient read/parse errors with backoff, capped `last_error` text.
2. Use existing `Provider.Load(ctx, ref)` pragmatically to reindex a **whole
   changed session** after a 500 ms quiet-period debounce. M0's `Load`
   currently parses whole JSONL and does not expose stable per-message
   checkpoints/offsets; metadata scanning alone cannot generate FTS text.
   Reindex-on-change is simpler and correct for merges, compactions,
   truncation and in-place rewrites; it can be expensive for a hot 38 MB
   session. On repeated writes, coalesce jobs and cap the delay at 2 s;
   benchmark and only then consider the optional `IncrementalLoader` in
   Proposed contract changes. Do not pretend metadata `Offset` maps directly
   to transcript message indices.
3. Extract each `Transcript.Messages[i]` (zero-based): include visible
   user/assistant **text**, reasoning text, and tool **name plus a short,
   plain-text input summary** (not full JSON, no tool output, patches,
   data-URIs, image bytes, secrets from credentials, or meta/system content).
   Reasoning is searchable but stays collapsed by default in the viewer;
   label reasoning/tool matches in the hit so users can expand that part.
   Normalize whitespace/control chars, remove the snippet marker control
   bytes, cap each message's combined indexed text at 8 KiB UTF-8 boundary,
   title at 1 KiB. Prefer text before reasoning/tool input under the cap.
   This is intentionally not exhaustive full-transcript search: locally
   ≈308 MB Claude files contain ≈6.7 MB text, ≈2.8 MB reasoning,
   ≈10.3 MB tool input vs ≈61.6 MB tool output, so indexing outputs is
   disproportionate. Surface the truncation rule in search help.
4. Build replacement docs off the main read path; in a short transaction,
   check the job revision still equals `sessions.fts_revision` and the row
   exists, DELETE existing `fts_docs` for the ref, INSERT title row (-1)
   plus indexed message rows, DELETE the job. Its triggers update FTS
   atomically. If revision became stale during `Load`, discard parsed data
   and retry latest revision; never publish stale indices. Avoid holding a
   SQLite write transaction while parsing a transcript. An in-flight deleted
   ref is discarded; cascading delete removes its docs/jobs.
5. Emit throttled `index:progress` (`FTSProgress`) at start, completion, and
   at most 4 times/s; frontend receives it through `api.ts`. Search still
   works on indexed rows while pending jobs run; exclude rows for a ref whose
   current revision does not match its indexed revision (store last completed
   revision in an additional `sessions.fts_indexed_revision INTEGER NOT NULL
   DEFAULT 0` column in migration 001). Update that field in the replacement
   transaction; `fts_indexed_revision = fts_revision` is the visibility
   guard. A new change queues a job and temporarily hides old hits for
   that ref rather than showing misleading message indices.

**Tests:** append/change replaces rows without duplicates; delete clears
FTS immediately; cancellation/restart resumes; stale worker cannot restore
removed data; title-only hit; exact index for a transcript with hidden meta,
reasoning and tool parts; 8 KiB Unicode cap and progress throttle. Create
fixtures with fake providers; don't index real user data in CI.

**Done when:** background indexing never blocks cached paint, jobs survive
restart, and search sees only complete revisions of existing sessions.

## M2-05 Search API and ranking (3 h)

**Files:** `internal/index/search.go`, `internal/index/search_test.go`,
`internal/app/search.go`, `frontend/src/lib/api.ts` type/wrapper/mock additions.

```go
type SearchFilter struct {
    Agents []model.AgentID `json:"agents,omitempty"`
    Dir string `json:"dir,omitempty"` // normalized path prefix, optional
    Limit int `json:"limit,omitempty"` // clamp 1..100, default 30
}
type SearchHit struct {
    Ref model.SessionRef `json:"ref"`
    MessageIndex int `json:"messageIndex"` // -1 for a title hit
    Snippet string `json:"snippet"` // escaped HTML, ONLY <mark> is allowed
    Score float64 `json:"score"`
    Kind string `json:"kind"` // title | text | reasoning | tool
}
func (d *DB) Search(ctx context.Context, query string,
    filter SearchFilter) ([]SearchHit, error)
// Wails-bound SessionService.Search(query string, filter SearchFilter)
```

**Query grammar:** plain Unicode words become ANDed FTS5 prefixes
(`foo bar` → `"foo"* AND "bar"*`); double-quoted phrases stay exact
(`"foo bar"` → `"foo bar"`, no suffix wildcard). Optional `agent:claude-code`
and `dir:/absolute/path` are parsed **outside** MATCH and passed as SQL
parameters; combine with explicit filter object by intersection. Treat
unbalanced quotes/empty tokens as validation errors, not FTS syntax errors.
Cap input (256 chars, 20 terms); reject query consisting solely of filters
with a helpful empty-search message. Avoid FTS operators (`OR`, `NEAR`, `-`,
`*`, parentheses) from raw input: tokenize/validate words, escape embedded
quotes by doubling, build MATCH only from quoted tokens and fixed `AND`.
Paths are matched as literal normalized directories (`cwd = ? OR cwd LIKE ?
ESCAPE '\'` with escaped `%`, `_`, `\` and a path separator), not SQL code.

**SQL shape** (parameterize `MATCH`, agent and dir; never interpolate user
text; `fts_indexed_revision` column is in migration 001):

```sql
SELECT d.ref,d.message_index,
       snippet(fts_messages,0,char(1),char(2),'…',16) AS excerpt,
       bm25(fts_messages) AS lexical, s.updated_at
FROM fts_messages
JOIN fts_docs AS d ON d.rowid=fts_messages.rowid
JOIN sessions AS s ON s.ref=d.ref
WHERE fts_messages MATCH ?
  AND s.fts_revision=s.fts_indexed_revision
  -- optional AND s.agent IN (?,...) / AND (s.cwd=? OR s.cwd LIKE ? ESCAPE '\')
ORDER BY lexical ASC, s.updated_at DESC
LIMIT ?;
```

`bm25` is lower/better; apply a **small** bounded recency boost in Go (e.g.
`score = -lexical + 0.1/(1+ageDays/7)`), with deterministic ties by ref and
message index. For ranking by the composite, fetch ≤3× limit candidates,
then sort and trim. `snippet()` emits sentinel control chars around matches;
strip those chars from indexed source, HTML-escape its entire output, then
replace only sentinels with `<mark>`/`</mark>` in Go. DOMPurify/safe rendering
in M1 still applies; never render an unescaped transcript as HTML. Store
`Kind` as a separate doc column (add `kind TEXT NOT NULL DEFAULT 'text'` to
`fts_docs` in migration 001) to distinguish reasoning/tool/title; one
mixed-content message row may be labeled `text` if it has ordinary text,
otherwise `reasoning` or `tool`.

**Tests:** prefix AND vs phrase, agent and directory path-boundary filters,
quotes/operator injection attempt, `MATCH` error handling, Unicode, empty
or too-long input, snippet highlighting/XSS (`<img onerror=...>` stays
escaped), lexical-vs-recency ordering, and title hit index -1. Mock API
implements `Search` for frontend tests.

**Done when:** search returns ranked, safe snippets with stable jump indices
and malformed input cannot become executable FTS syntax.

## M2-06 Search UI and jump-to-message (4 h)

**Files:** `frontend/src/lib/api.ts`, `frontend/src/lib/search.svelte.ts`,
`frontend/src/components/SearchBox.svelte`, `SearchResults.svelte`, existing
transcript component; `internal/app` only if M1's paging needs an around-index
adapter.

```ts
// api.ts: the sole binding/event adapter, real and mock implementations.
type SearchHit = { ref: SessionRef; messageIndex: number;
  snippet: string; score: number; kind: 'title'|'text'|'reasoning'|'tool' };
search(query: string, filter: SearchFilter): Promise<SearchHit[]>;
getMessages(ref: SessionRef, offset: number, limit: number): Promise<Message[]>;
// Optional convenience if M1 cannot request an arbitrary offset:
getMessagesAround(ref: SessionRef, index: number, radius: number): Promise<MessagePage>;
```

**Steps**
1. `/` focuses search unless an editable field has focus (later M3 keyboard
   navigation owns other shortcuts). Debounce typing by ≈150 ms, cancel/ignore
   out-of-order promises, show loading/empty/error and `index:progress` while
   indexing is incomplete. Retain the active filter in the app store;
   displaying snippets does not require opening the transcript.
2. On hit click, select the ref (including child sessions), await header and
   transcript readiness, request the page containing `messageIndex` with
   `GetMessages(ref, max(0,index-20), 50)` (or `GetMessagesAround`). A title
   hit (`-1`) opens at 0. Seed the virtualizer with the requested offset and
   scroll to **global** item index, not page-local 20; do not load 10k earlier
   messages. If a concurrently changed transcript moved/deleted the index,
   show a nonfatal stale-result notice and offer re-search.
3. Expand a matched reasoning/tool section if its `kind` says so, highlight
   matching rendered text briefly (safe text-node matching or sanitized
   `<mark>` markup), and restore prior focus after navigation. A meta-hidden
   item should remain hidden unless it is the target; M2-04 does not index
   meta rows, but indices include them and the virtualizer must account for
   their positions. Preserve source page anchoring after dynamic expansion.
4. Add keyboard/virtualizer tests with a mock 10k-message transcript and
   title/subagent hits; real Wails binding imports stay confined to `api.ts`.

**Done when:** clicking a hit in a long transcript loads only a nearby page,
scrolls to the exact message and visibly marks the match.

## M2-07 fsnotify watchers and targeted refresh (4 h)

**Files:** `internal/watch/watch.go`, `internal/watch/linux.go`,
`internal/watch/watch_test.go`, integration with `internal/index/refresh.go`.

```go
type Change struct {
    Agent model.AgentID
    Paths []string // absolute changed source files, or nil = full reconcile
}
func Start(ctx context.Context, providers provider.Set,
    onChange func(Change)) (close func() error, err error)
```

**Steps**
1. `fsnotify` is **not recursive on Linux**. Enumerate/explicitly add
   Claude `projects/`, every `projects/*` encoded cwd, each session's
   `subagents/` directory; also Claude `sessions/` for live metadata hints.
   When a new project/session/subagents dir is created, add it and scan its
   contents immediately (a file may already have appeared). Ignore tool
   outputs, `.meta.json` except subagent metadata, and credentials.

## Proposed contract changes

M0 contracts remain unchanged. These are **optional additions** or
conventions for M1/M2 coordination; adopt only when the dependent
implementation needs them.

1. `provider.PathScanner` (optional):
   ```go
   type PathScanner interface {
       ScanPaths(ctx context.Context, prev ScanState, paths []string) (ScanResult, error)
   }
   ```
   Return a complete merged `State`; do not mark unrelated sources removed.
   Watchers fall back to the existing `Provider.Scan` if absent. Full
   reconciliation runs periodically regardless. Not required for correctness.
2. `provider.IncrementalLoader` (future performance optimization, **not**
   required for M2's 4 h FTS task):
   ```go
   type IncrementalLoader interface {
       LoadFrom(ctx context.Context, ref model.SessionRef,
           since SourceState) (messages []model.Message,
           next SourceState, reset bool, err error)
   }
   ```
   Define message index/assistant merge boundary semantics and state
   provenance before implementing; cannot naively reuse metadata scan
   checkpoints. M2 defaults to debounced full-session `Load` on changes.
3. `internal/app.SessionService` gains `Search`, `GetDiagnostics`,
   `ClearCacheAndRebuild` and, only if M1's `GetMessages` cannot page from
   arbitrary global indices, `GetMessagesAround`. `api.ts` mirrors these
   in real/mock backends and owns all Wails event subscriptions. An internal
   catalog method for **volatile** live-status mutation may be added to M1
   without altering M0 `SessionMeta`/`Provider` signatures.
4. If M1's Claude/Codex file scan cannot distinguish same-size replacement,
   track file identity in provider-private `SourceState.Checkpoint` (without
   adding a field to M0) or schedule a verification scan. Preserve the
   M0 `Size/ModTimeNs/Offset/Checkpoint` JSON shape.

## Risks and explicit limits

- Full-session `Load` for every hot-file FTS change can cause I/O churn;
  one worker, debounce and revision checks constrain it. Profile first; an
  incremental loader is a separately scoped optimization.
- `mtime`/`time_updated` and filesystem events are not perfect change
  or liveness proofs. Periodic reconciliation, equal-cursor rereads and
  file-shrink handling close common gaps; verified liveness is Claude-only.
- Search is intentionally capped and excludes large tool outputs/attachments;
  this is a documented privacy/size trade-off rather than full byte-for-byte
  transcript search. Cache contains sensitive indexed text: permissions and
  the clear-cache action are essential.
- FTS5 SQL functions operate on the virtual-table query context; test the
  actual modernc driver on Linux and macOS. Version drift/rebuild and
  external-content triggers must be tested against cascade deletion.
- Wails events can arrive after an initial frontend request or during a
  rebuild. Treat them as invalidations, refetch the authoritative catalog,
  and guard asynchronous responses with generation/request ids.
