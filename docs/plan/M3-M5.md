# M3–M5 — Polish, opt-in management, and distribution: detailed plan

Covers M3-01 … M3-12, M4-01 … M4-03, M5-01 … M5-06 in
[TASKS.md](../../TASKS.md). Estimates below include task tests; M4 remains optional
pending SPEC §14 Q1. M0's [shared contracts](M0.md) are authoritative: this
plan does not amend that document. Proposed amendments are collected at the
end rather than silently changing `SessionRef`, `Provider`, or `paths.Roots`.

Assume M1 supplies per-root provider instances, `internal/scan`'s catalog,
`internal/group`'s `Node` tree (dir-agent, agent-dir, flat), a Wails v2
`internal/app.SessionService`, and Svelte 5/TS `frontend/src/lib/api.ts` as
the **only** generated-binding/event gateway (also mockable). Assume M2 owns
`index.db`, indexed session columns, FTS5, the watcher, `catalog:changed`,
live refresh, and diagnostics. Use M2's actual migration/API names after it
lands; illustrative SQL below specifies semantics, not an alternative schema.

## Shared implementation rules

- Read-only remains the default. No write/remove/rename calls in
  `internal/provider/**`; M4 writes to tool storage **only** through
  `internal/manage`, behind opt-in and a fresh live check. M3's writes target
  only our config/state, cache (M2), or user-chosen export file.
- Do not read `.credentials.json`, `auth.json`, or OpenCode
  `credential`/`account` tables. Never place a transcript, terminal command,
  root path, or `config.toml` in logs/CI artifacts. No network calls at
  runtime; invoking a local tool's CLI in M4 must not silently contact remote
  servers.
- All new app bindings use `context.Context` internally, propagate errors
  with a useful provider/ref label, and return safe display errors to the UI.
  Cancel pending queries/exports when changing sessions. Enforce explicit
  sort-field allowlists; all SQL **values** are bound parameters.
- Paths may be missing or symlinked. `pathutil.NormalizeDir` and
  `GitResolver.Resolve` are the only filesystem-based normalizers; never
  decode Claude's lossy project-directory encoding. Treat unknown/NULL
  token and cost data as unknown, not automatically zero in explanatory UI.
- Tests use temp roots, synthetic fixtures, fake clock/executor where relevant;
  never use a person's session store in destructive tests. Run `make test`
  and lint/Svelte checks per TASKS.md; integration checks require explicit
  local opt-in.

## M3-01 Backend filters (3 h)

**Files:** `internal/catalog/filter.go` (or M1's catalog package),
`internal/index/query.go` (M2 SQL adapter), `internal/group/group.go`,
`internal/app/session_service.go`, corresponding `*_test.go`.

```go
type Filter struct {
    Agents       []model.AgentID `json:"agents,omitempty"`
    From         *time.Time      `json:"from,omitempty"`  // UTC inclusive
    Until        *time.Time      `json:"until,omitempty"` // UTC exclusive
    Models       []string        `json:"models,omitempty"`
    Archived     string          `json:"archived"`        // "active" | "all" | "only"
    HasSubagents bool            `json:"hasSubagents,omitempty"`
    LiveOnly     bool            `json:"liveOnly,omitempty"`
}
func (f Filter) Validate() error
func (f Filter) Match(m model.SessionMeta, hasChild bool) bool
func (q *Queries) List(ctx context.Context, f Filter, sort Sort) ([]model.SessionMeta, error)
```

TS shape in `frontend/src/lib/api.ts`:

```ts
export type Filter = {
  agents: AgentID[]; from?: string; until?: string; // ISO UTC instants
  models: string[]; archived: 'active' | 'all' | 'only';
  hasSubagents: boolean; liveOnly: boolean;
};
```

**Steps**
1. Default to `archived="active"`, all agents/models, no date bound.
   The date UI converts local calendar boundaries into UTC `from`/`until`
   (end date + 1 local day); never compare formatted dates in SQL.
   Reject `from >= until`, invalid enum, unknown agents, unbounded/oversized
   model strings and too many choices; trim/dedupe exact model values.
2. Apply the **same predicate** to catalog snapshots and M2 queries. Build
   `WHERE` fragments with placeholders (`s.agent IN (?,...)`,
   `s.updated_at >= ?`, `s.updated_at < ?`, `s.model IN (?,...)`,
   `s.archived = ?`, `s.live = 1`). For `HasSubagents`, prefer M2's indexed
   `has_children` column or a correlated `EXISTS (SELECT 1 FROM sessions c
   WHERE c.agent=s.agent AND c.root=s.root AND c.parent_id=s.id)`; do not
   count another root's child. Bind UTC timestamps in M2's storage unit
   (epoch milliseconds if that is its schema), not RFC3339 strings if the
   column is numeric. Whitelist column names; **never** concatenate values.
3. `Filter.Match` mirrors SQL for startup-before-index/failure fallback.
   Compute `hasChild` from all catalog rows **before** filtering so a parent
   still qualifies when its children are hidden. M2's `Live` is mutable: use
   its current live overlay (or refresh indexed `live`) to keep both paths
   identical. Absent model does not match a selected model.
4. Filter session rows once, then rebuild the M1 `group.Node` tree and counts
   from matching rows. Keep child nesting only when parent matches; otherwise
   display a matching child as an orphan with parent context, rather than
   silently losing it. Search (M2) accepts this same validated filter.

**Tests:** table comparisons of SQL vs `Match` over active/archived/null
model, UTC boundary, child in other root, live transitions and absent parent;
SQL-injection model string; filtered tree/session counts agree. **Done when:**
all six filters work through both data paths and tree counts match rows.

## M3-02 Filter UI and state persistence (3 h)

**Files:** `frontend/src/lib/stores/filters.ts`, filter chips/popover component
in `frontend/src/components/`, `frontend/src/lib/api.ts`,
`internal/app/state.go`, `internal/app/session_service.go`, tests.

```go

    Version int    `json:"version"`

    Group   string `json:"group"`
    FoldRepos bool `json:"foldRepos"`
```

**Steps**
1. Put state at `filepath.Join(paths.Roots.Config, "state.json")`, **not**
   `config.toml` (user-editable defaults) and not `index.db` (clear-cache must
   preserve preferences). File/directory mode `0600`/`0700`; version field,
   defaults on first run, recover invalid JSON by warning and resetting just
   UI state. Debounce writes (≈250 ms); atomic temp file in the same directory
   + rename, never truncate a known-good state on crash.
2. Initialize from config defaults only when no state exists. Validate loaded
   filter against currently detected agents; keep unknown agent entries in
   disk state if temporarily unavailable but don't block a working UI.
   State is per app installation and persists **across restarts**, not just
   for one OS process (TASKS.md acceptance).
3. Chips represent agent/model/date/archived/children/live. Popover has
   accessible labels, Clear all, and an explicit archived tri-state; remove a
   chip to clear its predicate. Request updates immediately, cancel stale
   fetches or use a request generation so older results cannot overwrite
   newer ones. Search results, list and group tree use one filter store.

**Tests:** store serialization, date-zone boundary (DST), invalid state
recovery, stale-request ordering, clear-all. **Done when:** every chip updates
the tree/list/search immediately and the state survives relaunch.

## M3-03 Stable sort (2 h)

**Files:** `internal/catalog/sort.go`, M2 query adapter,
`frontend/src/components/SessionList.svelte`, state store/tests.

```go
type Sort struct { By string `json:"by"`; Desc bool `json:"desc"` }
// By: "updated" | "created" | "messages" | "tokens" | "cost".
```

**Steps:** Permit only the five enum values in `ORDER BY` via a fixed

the select and direction toggle; persist through M3-02's state.

**Tests:** ties across agents/roots, NULL tokens/cost, direction, SQL vs Go
order, restart. **Done when:** all five sorts are stable and persisted.

## M3-04 Repository folding (3 h)

**Files:** `internal/group/group.go`, `internal/pathutil/git.go` (only if a
small hint adapter is necessary), `internal/app/session_service.go`, sidebar
toggle/store, grouping tests.

```go
type GroupOptions struct { Mode group.Mode; FoldRepos bool }
func Group(metas []model.SessionMeta, opts GroupOptions) []group.Node
```

**Steps**
1. M0 stores `SessionMeta.RepoRoot = RepoInfo.MainRoot` (not
   `RepoInfo.Toplevel`), which already folds Git linked worktrees, including
   `.claude/worktrees/*`, with the main checkout. M1 OpenCode's `project.worktree`
   and `worktree(project_id,directory)` give extra evidence when a cwd is
   missing: use the project's **specific** worktree match, then resolve that
   worktree through `GitResolver` to its `MainRoot`. Ignore `project_id=global`
   and its `/` sentinel. Never fold unrelated repos merely because paths share
   a prefix. Treat stale DB hints as hints, not proof if Git resolves a
   different existing checkout.
2. When `FoldRepos`, group using normalized `RepoRoot` if present, otherwise
   normalized CWD; flat mode remains flat. Keep each row's actual CWD for
   terminal/resume. A node label shows the main repo basename; a subtitle
   distinguishes `worktree: <basename> · <branch>` when the session's
   `GitResolver.Resolve(CWD).Toplevel != MainRoot` (or the verified OpenCode
   worktree directory matches), otherwise `subdir: <relative path>`; tooltip
   shows full actual and main paths. Do **not** label every subdirectory a
   worktree. Directory existence/missing badge follows the actual CWD.
3. Aggregates and row counts reflect current filters, with no double count
   of a session in main/worktree groups. Preserve expansion via stable keys
   containing the fold flag. Toggle persists in `state.json`; display why
   a no-repo session stays separate.

**Tests:** temp repo + `.git`-file linked worktree + subdir, deleted cwd,
OpenCode mapped worktree, global project, symlink, two distinct repos sharing
names, fold off/on. **Done when:** linked worktrees on this machine group
under the main repo and retain honest worktree labels.

## M3-05 Configuration file and root overrides (3 h)

**Files:** `internal/config/config.go`, `internal/config/config_test.go`,
`internal/provider/all/all.go`, `internal/paths` caller; add
`github.com/BurntSushi/toml` to `go.mod`.

Complete proposed `config.toml` example (defaults shown; omitted keys use
these defaults):

```toml
version = 1

[providers.claude-code]
enabled = true
roots = ["/home/dev/.claude", "/mnt/agent-profiles/work/.claude"]

[providers.codex]
enabled = true
roots = ["/home/dev/.codex"]

[providers.opencode]
enabled = true
roots = ["/home/dev/.local/share/opencode"]

[view]
grouping = "dir-agent" # dir-agent | agent-dir | flat
fold_repositories = false
hidden_directories = ["/home/dev/work/private"] # exact directory/subtree
sort = "updated" # updated | created | messages | tokens | cost
theme = "system" # system | light | dark

[terminal]
# Empty means Automatic. An id of a terminal detected on this computer
# (e.g. "kitty", "iterm2"), never a command; see M8-12 in M8.md.
app = ""

[manage]
enabled = false
allow_permanent_delete = false # OpenCode only; requires separate confirmation
```

```go
type Config struct {
    Version int `toml:"version"`
    Providers map[string]ProviderConfig `toml:"providers"`
    View ViewConfig `toml:"view"`
    Terminal TerminalConfig `toml:"terminal"`
    Manage ManageConfig `toml:"manage"`
}
type ProviderConfig struct { Enabled bool `toml:"enabled"`; Roots []string `toml:"roots"` }
type TerminalConfig struct { Command []string `toml:"command"`; Resume bool `toml:"resume"` }
func Load(path string, defaults paths.Roots) (Config, error)
func Save(path string, c Config) error
func Validate(c Config) error
```

**Steps**
1. First-run config may remain absent; `Defaults(paths.Roots)` supplies the
   single per-provider M0 root, system theme, updated sort, and destructive
   actions off. Treat a present `roots=[]` as intentional no roots only if
   provider is disabled; for enabled providers, reject it. Explicit roots
   **replace** the environment-derived default; do not concatenate implicit
   and explicit roots. Path expansion: `~` only at prefix, absolute paths,
   Clean/EvalSymlinks where existing; no shell/env interpolation in strings.
2. Use `toml.Decode`/`toml.DecodeFile` and `MetaData.Undecoded()` to reject
   misspelled keys, unknown providers, version > 1, invalid enum/template,
   duplicate canonical roots within one provider, relative paths, and any
   overlap between distinct provider roots that would scan unrelated data.
   Reject an attempted credential filename as a root. Do not read anything
   under the root during **validation**. Include key path and line (where
   available) in errors. Apply defaults to *missing* booleans carefully:
   decode onto `Defaults(...)`, not a zero-value struct that disables tools.
3. Build a provider per configured root (M0 requires explicit roots) with a
   shared `GitResolver`; M1/M2 catalog/index/watcher must key them by
   `(agent, root)` rather than agent alone. Session IDs may recur across two
   Claude/Codex/OpenCode roots; see **Proposed contract changes**. Never pass
   user-supplied `SessionRef.Root` directly to a filesystem path: resolve it
   against this registry first.
4. `Save`: write a 0600 temp file in `Roots.Config`, fsync, atomic rename;
   retain previous file on invalid config/write failure. Hot-apply a valid
   change transactionally: construct the new provider set, stop removed-root
   watches, scan added roots, remap catalog, reindex M2, emit
   `catalog:changed`. Keep old config active on parse/apply failure. Changes
   to display defaults do not overwrite explicit `state.json` choices.

**Tests:** defaults, TOML round-trip, malformed/unknown keys, duplicate and
relative roots, disabled provider, duplicate session UUID in distinct roots,
failed apply preserving old watchers/catalog. **Done when:** multiple roots
are independently detected, listed, and hot-applied without collisions.

## M3-08 Export Markdown (3 h)

**Files:** `internal/export/markdown.go`, `internal/export/export_test.go`,
`internal/app/session_service.go`, export menu/API/tests.

```go
type Options struct { ShowMeta bool; ShowReasoning bool }
func Markdown(ctx context.Context, w io.Writer, t model.Transcript, opt Options) error
func (s *SessionService) ExportSession(ref model.SessionRef, format string, opt Options) error
```

**Format contract (UTF-8, LF, deterministic):** `# <escaped title>`;
metadata table (agent/id, actual cwd, branch, model, timestamps, counts,
tokens/cost when known); then chronological `## 1 · User — 2026-…` /
`## 2 · Assistant — …` / `## … · System`. Each text part is markdown text;
reasoning gets a `> Reasoning` label and is omitted unless opted in; meta
messages are omitted unless opted in. A paired `tool` is one collapsed
`<details><summary>Tool: name · status</summary>` block containing fenced
JSON input and fenced/plain output, with `_(truncated)_` when a blob wasn't
loaded. Patch/file/compaction/notice get distinct readable labels; file
parts list name/MIME/ref rather than inlining huge data. Include child link as
an app-local textual reference, not a broken external URL.

**Steps:** Stream render to `io.Writer` with ctx checks; sanitize HTML in
transcript text for Markdown targets (escape `<`, `&` so injected `<script>`
or `</details>` cannot break structure), choose backtick fence length longer
than the longest literal run in input/output, and avoid writing raw tool JSON
as HTML. Keep line lengths sane but do not truncate ordinary user text.
Expose export in the header via `api.ts`; choose output path **in the Go
binding** with Wails v2 `runtime.SaveFileDialog(s.ctx,
runtime.SaveDialogOptions{DefaultFilename: "session.md", Filters: …})`;
empty path means cancel. Write user-approved destination with `0600` temp
file in same directory then rename (warn before overwriting, because rename
bypasses dialog conflict handling); clean only our temp on error. A lazy
blob may remain summarized and marked truncated; don't unexpectedly load
hundreds of MB just for export.

**Tests:** Markdown golden with tool pair, inner backticks, HTML payload,
meta/reasoning toggle, Unicode and cancellation. **Done when:** exported
Markdown is readable and the golden fixture matches exactly.

## M4 safety model (applies to M4-01 … 03)

Explicitly opt in with `[manage].enabled=true`; the default build remains
read-only. Every action re-resolves the `SessionRef` in the current provider
registry, checks that its source path is inside that exact configured root
using `filepath.Rel` plus `Lstat`/symlink checks, and obtains a fresh M2 live
check **at execution time** (not a stale badge). If live status is unknown,
fail closed. Child/subagent liveness also blocks parent actions. Reject
nested/bare paths, credentials, DB files, arbitrary overrides, and root
itself. Serialize mutations per ref and coordinate watcher/catalog rescans;
never edit M2 cache as if it were the source of truth.

## M4-01 Linux Trash transport (3 h)

**Files:** `internal/manage/trash.go`, `trash_linux.go`, `trash_darwin.go`
(stub returning unsupported), tests. **Not** under `internal/provider`.

```go
type Trash interface { Move(ctx context.Context, absPath string) error }
type GioTrash struct { Exec func(context.Context,string,...string) error }
func (g GioTrash) Move(ctx context.Context, absPath string) error
```

**Decision:** use installed `gio trash -- <absolute-path>` as the Linux
transport, rather than reimplementing the freedesktop Trash spec in 3 h.
Check `gio` with `exec.LookPath`; if absent, disable Trash and explain how
to install GIO (do **not** silently fall back to `os.Remove`, `mv`, or
`xdg-open`). Pass one path per invocation as argv, never through a shell.
Keep validation/coordination in `internal/manage`; GIO is only transport.

**Expected spec behavior to verify in integration:** for the home device,
`$XDG_DATA_HOME/Trash/{files,info}` (default `~/.local/share/Trash`);
entry `info/<unique-name>.trashinfo` has `[Trash Info]`, URL-percent-encoded
`Path=` (absolute for home trash, topdir-relative for per-mount trash) and
local `DeletionDate=YYYYMMDDThhmmss`; payload in `files/<unique-name>`.
On another filesystem use that mount's valid sticky, writable `.Trash/<uid>`
or private `.Trash-<uid>`; don't copy to home trash across devices. Colliding
names must acquire unique matching data/info basenames. GIO handles mount
selection, collision reservation, permissions and recoverable file-manager
integration. Trash may be unavailable on a filesystem; report failure
without claiming the session was deleted. A multi-path operation is not
atomic: expose which paths moved and offer the file manager's Trash for
manual restore (never auto-restore to a potentially active session).

**Tests:** fake executor verifies no shell/path args, CLI absent/error; opt-in
integration with temp `XDG_DATA_HOME` verifies `.trashinfo` path/date and
same-name collisions, and a separate mounted-volume manual test for
`.Trash-<uid>`. **Done when:** trash entries appear in the Linux file manager
and can be restored; missing GIO never triggers permanent deletion.

## M4-02 Claude and Codex actions (4 h)

**Files:** `internal/manage/actions.go`, `claude.go`, `codex.go`,
`internal/app/session_service.go`, management dialog components/tests.

```go
type Action string // "trash" | "archive"
type Preview struct { Ref model.SessionRef; Paths []string; Children int; Reversible bool; Warning string }
func (s *SessionService) PreviewAction(ref model.SessionRef, action Action) (Preview,error)
func (s *SessionService) ManageSession(ref model.SessionRef, action Action,
    confirmedToken string) error
```

**Steps**
1. UI is hidden unless enabled; preview enumerates affected children and
   explains effects before showing a button. Copy for Claude: **“Move this
   Claude session transcript and its subagent/tool-result directory to Trash?
   You can restore these files from Trash. History and file-history references
   will remain.”** Confirm with a single click in the preview dialog (no
   typed confirmation; permanent deletions show a “cannot be undone” warning
   and a **Delete Permanently** button) and use a
   short-lived preview token tied to ref/action/path set; revalidate all
   paths, live state and opt-in after confirmation (TOCTOU). On any partial
   GIO failure, list moved vs remaining paths and rescan.
2. Claude: trash the selected main
   `projects/<encoded-cwd>/<uuid>.jsonl` **and** sibling `<uuid>/` tree,
   including `subagents/*.jsonl`, `*.meta.json`, `tool-results/*.txt`;
   don't trash the whole `projects/<encoded-cwd>` directory. For a child
   session, trash only its `agent-*.jsonl` and matching `agent-*.meta.json`
   after checking parent/child live guard; leave shared parent/tool-results
   unless ownership is provable. Never touch `~/.claude/history.jsonl`,
   `file-history/`, or `session-env/`; these may contain stale references
   and user-visible history. No Claude archive API is assumed: expose
   “Move to Trash”, not a misleading Archive action.
3. Codex: official CLI on this machine (`codex-cli 0.156.1`) supports
   `codex archive <UUID>`, `codex unarchive <UUID>`, `codex delete <UUID>`.
   Prefer **`codex archive <UUID>`** (and unarchive when already archived):
   it keeps rollouts, updates its `threads` state coherently, and may move
   a rollout to `archived_sessions/`; verify effects with a test fixture on
   a disposable `CODEX_HOME`. Set `CODEX_HOME` to the session's registered
   root and cwd to its actual directory, remove any `--remote` flags, impose
   timeout, capture bounded stderr, then rescan. If CLI/version doesn't
   support archive, hide action with explanation. Do **not** manually trash
   `rollout-*.jsonl` while leaving `threads.rollout_path`/`archived` stale.
   Also **do not** call `codex delete`: it is permanently destructive and
   conflicts with the Trash/restore promise. (*As built:* Codex uses
   `codex delete --force`, gated by the separate `allow_permanent_delete`
   opt-in (M4-04); archive is deferred to M4-06.) Mark Codex “Archive” reversible
   (via unarchive), not “Trash.”
4. Recheck fresh live/unknown status for Claude and Codex, including children,
   even after preview. Invalidate M2 index/search for removed/moved sources
   via normal scan; emit `catalog:changed`. Preserve a recoverable error if
   Codex CLI fails; never update state DB directly.

**Tests:** preview token expiry/path change, symlink escapes, child guard,
active/unknown live refusal, Claude exact file set/partial failure, fake
Codex CLI with archive/unarchive, watcher rescan. **Done when:** Claude
entries restore from Trash and Codex archiving leaves CLI resume/index
coherent; no live session can be acted on.

## M4-03 OpenCode official management path (3 h)

> **As built (2026-09-28):** v2 copies are deleted with
> `opencode session delete --standalone`. The CLI only sees v2, so v1 rows
> are deleted directly in one SQL transaction (`part`, `session`, and
> `event_sequence` for v1-only IDs; no other table). Deletion is refused
> while `kv['migration.v1-v2']` is not `completed`, since the standalone
> CLI would resume the migration. No archive exists yet (M4-06). The plan
> below is the original design.

**Files:** `internal/manage/opencode.go`, action availability service/UI,
unit tests. Never mutate `opencode.db` or legacy JSON files directly.

**Research/decision:** installed `opencode v2.0.18` exposes `opencode session
list|delete|export|import`; `opencode session delete <sessionID>` explicitly
**deletes the session and its children** (no Trash), and there is no
`session archive` subcommand. The local server's supported API has
`DELETE /session/:id`; archiving is a session update (`PATCH /session/:id`
with `time.archived`, version-dependent). Prefer the local official API via
`opencode api`/SDK only after verifying the running version's operation/schema;
do not guess request JSON or call a remote `--server`. A failing schema probe
means **hide Archive** for that installation, rather than writing to DB.

**Steps:** For verified v2/v1 DB-backed sessions, offer Archive/Unarchive
when the locally detected CLI/API accepts it; update `time.archived` with
an official session update, and verify the resulting session row on rescan.
Archiving a parent may not cascade: enumerate each child, guard all live,
update children explicitly or state clearly they remain unarchived. For
permanent deletion, require both `manage.enabled` **and**
`manage.allow_permanent_delete`, and a confirm dialog warning **“OpenCode
will permanently delete this session and its child sessions. It will not go
to Trash and cannot be restored.”** (one click on **Delete Permanently**, no
typed confirmation); use `opencode session delete <ID>`
against a verified **local** server/root, no shell and no auto-spawn/remote
server. Check child list and liveness again immediately before call. If
root override cannot be targeted safely by the CLI, or CLI/version lacks the
official operation, **hide Delete**; legacy-only records also remain
read-only. Never advertise OpenCode deletion as recoverable, and never call
`DELETE` as a fallback for failed Archive. Reindex after success.

**Tests:** fake CLI/API advertises supported/unsupported archive, malformed
response, child cascade and live refusal, wrong root/server, CLI failure,
no direct SQLite write. Manual disposable-root test verifies whether
archive/unarchive actually work for target OpenCode version before enabling.
**Done when:** official operations work on a verified local target, or
unsupported actions are safely hidden without writing to storage.

## Proposed contract changes (review with M0/M1/M2 owners before coding)

1. **Multi-root identity is mandatory for M3-05.** M0 currently has
   `model.SessionRef{Agent, ID}` and `Key()` = `agent+":"+id`, while
   `provider.Set.Get(agent)` assumes one instance. Add a stable canonical
   `Root string `json:"root"`` to `SessionRef`, include it in an unambiguous
   length-/base64-encoded `Key()` (never delimiter-join raw paths), and
   identify providers by `(Agent, Root)` via `Provider.Root() string` plus
   `Set.Resolve(ref)`. Migrate old M2 `(agent,id)` keys to
   `(agent,root,id)` after a root-aware rescan; scope parent links,
   child refs, FTS rows, watcher keys, live maps, UI selection and
   `SourceState` by root. The API must accept only registered roots;
   canonical root IDs can instead be opaque stable hashes if all layers
   agree, but do not silently prefix the tool's original session ID.
2. **Stats data availability.** M2 must expose indexed `updated_at`,
   `created_at`, `message_count`, `total_tokens`/known flag, `cost_usd`/known
   flag, `archived`, `live`, `model`, `parent_id`, `repo_root`, `cwd` and
   `(agent,root,id)` keys, or an equivalent query view. If M2's schema
   differs, adapt M3 SQL instead of changing M0's `SessionMeta`. Cost-known
   cannot be inferred from `CostUSD == 0`; a cache-only known flag is okay.
3. **Raw source lookup.** M0's `Provider.Blob(ref,key)` is for lazy
   tool/file payloads and doesn't guarantee a record-to-message map.
   M3-11 proposes optional `provider.RawRecordReader` plus provider-private
   message locators (or a rigorously specified `raw:` Blob key). Preserve
   the base `Provider` interface for older plugins; unsupported providers
   show unavailable, not guessed raw JSON.
4. **Codex/OpenCode action availability.** Add a small capability/preview
   registry in `internal/manage`, **not** a mutation method on M0's
   read-only `Provider`. Fresh live status must be authoritative enough for
   M4; when heuristic/unknown (especially Codex/OpenCode or Darwin pid
   reuse), fail closed. `paths.Roots` remains the M0 single-default-roots
   struct; configured multiple roots live in `internal/config`, not in a
   silent change to `paths.Roots`.

**Research notes:** Codex's official [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
confirms archive/unarchive/delete and permanent delete semantics; local
`codex --help` (0.156.1) and `opencode session --help` (2.0.18) confirmed
the commands noted above. Trash behavior follows the
[freedesktop Trash specification](https://specifications.freedesktop.org/trash-spec/latest/).
Version-sensitive OpenCode archive JSON/API behavior remains a **probe before
enabling**, not an assumed contract.
