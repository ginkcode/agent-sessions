## Goal

Provide a standalone frontend code-diagnostics store and transport-neutral API
using finalized [CD-01](CD-01.md) contracts. Reconcile snapshots/events safely
under host switches, generations, and truncation with mock-driven focused tests.

## Current code grounding

- `frontend/src/lib/api.ts` defines BackendAPI, Wails calls, mock selection, event
  subscriptions, and `guardEpoch`; existing `getDiagnostics` is scanner health.
- `frontend/src/lib/link.ts` rejects stale promise replies by connection epoch,
  but event callbacks still need explicit identity/sequence validation.
- `stores/files.svelte.ts` owns directory, cached tabs, drafts, revisions, and
  mutation uncertainty; its editor `version` is not automatically an LSP version.
- `frontend/test/file-drafts.test.mjs` uses `loadServerModule`, fixtureStore, and
  deferred promises to test rune-store races without mounting the full UI.

## Concrete implementation steps

1. Add distinct code-diagnostics types and BackendAPI operations/events from CD-01,
   including capability, identity, provider state, coverage, freshness, batches,
   truncation, and sequence metadata. Leave existing Diagnostics types untouched.
2. Implement Wails API mappings and MockBackendAPI behavior following existing
   bridge/error/epoch conventions. Expose absent capability as unsupported, not
   an exception that prevents opening the file dialog.
3. Create `stores/codeDiagnostics.svelte.ts` with explicit attach/detach and
   lifecycle entry points. Keep process/results state out of FilesStore; do not
   add a second owner of draft text, revision, selection, or tab close policy.
4. Subscribe and reconcile attach/snapshot/events exactly as CD-01 specifies.
   Buffer only bounded in-flight data, assemble batches atomically, reject stale
   snapshots, and deduplicate events without dropping newer replacements.
5. Check backend epoch, canonical project identity, attachment token, generation,
   provider run, and sequence as applicable before applying any reply/event.
   Same root string on another host or reconnect must not reuse old identity.
6. Detect sequence gaps/incomplete snapshots and request bounded resnapshot;
   coalesce recovery requests, expose stale/partial/truncated state, and avoid
   infinite retry loops or presenting incomplete findings as clean success.
7. Implement explicit approval/revoke/run/cancel/retry store actions and provider
   availability states. Stage 1 must not run checks automatically on attach/open
   or advertise live support because future document types exist.
8. Expose stable read-only projections for CD-11…CD-15: provider-owned sets,
   grouped findings, exact-dedup attribution/counts, coverage/status, and inline
   eligibility by saved revision/dirty state. Keep file-level findings visible;
   never apply saved-file ranges over a dirty draft.
9. Add host/disconnect/hide/replacement cleanup and unsubscribe hooks without
   clearing FilesStore drafts or editor history. Document minimal lifecycle wiring
   expected from later dialog tasks; do not build controls or document sync now.

## Contract and security considerations

- Follow CD-01; UI convenience must not weaken backend trust or token scoping.
- Diagnostic messages remain plain strings, never HTML, persisted storage, or
  telemetry. Keep source/host attribution and uncertain freshness intact.
- Distinguish no reported problems from complete clean coverage; no implicit
  save, automatic checker execution, tool installation, or draft upload.
- Exact dedup keys preserve differences in range, severity, message, and code.

## Focused tests

- Mock snapshots/events before and after attach reply, out-of-order/duplicate
  sequences, incomplete batches, gaps, truncation, empty provider replacement,
  failure/cancel stale retention, and independent missing/available providers.
- Deferred replies across host switch/reconnect/revoke/detach; old callbacks after
  unsubscribe; same path on two hosts; bounded resnapshot retries and buffers.
- Dirty saved-file ranges suppressed, file-level findings retained, exact dedup
  attribution/counts, drafts/history untouched, and capability-absent browsing.
- Run frontend tests and type checking using existing package scripts.
