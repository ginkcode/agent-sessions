## Goal

Reconcile disk changes on dialog reopen, explicit refresh, and before project-check
reruns. Implement bounded server file-watch support or a truthful stale fallback;
never imply continuous workspace synchronization when absent. APIs await CD-01.

## Implementation steps

1. Inventory each supported adapter's actual file-watch registration behavior and
   define a bounded implementation versus explicit unsupported/stale policy.
2. Reconcile relevant file revisions and opened documents on reopen during idle
   grace; after expiration, reinitialize sessions and reopen actual displayed text.
3. Wire explicit refresh and pre-check refresh to revision/freshness transitions.
   Avoid synchronous discovery/scanning/process startup in dialog rendering.
4. Preserve dirty/conflicted/uncertain drafts when external disk text differs;
   update saved-file context and versions without replacing user text or undo state.
5. Reconcile confirmed external rename/delete/reload using lifecycle operations,
   clearing deleted-path sets and rejecting late old-URI publications.
6. If implementing watches, allowlist registration methods/options and constrain
   patterns, roots, count, queue length, event rate, and platform resources.
7. Batch/coalesce contained file events and support bounded unregister/cleanup.
   Overflow, dropped events, unsupported globs, or failures must mark coverage stale
   and require reconciliation, not silently retain a continuous-sync claim.
8. Otherwise reject unsupported watch registration safely and show explicit stale
   unopened-file coverage until reopen/refresh/rerun reconciliation occurs.
9. Keep checker disk snapshots distinct from LSP document snapshots; a rerun refresh
   does not certify an unversioned push against a draft or save anything implicitly.
10. On revocation/disconnect/host change/idle eviction, stop watchers and invalidate
    generation-scoped events; do not deliver old-root changes into new sessions.

## Contract and security considerations

- Watchers and language processes run on the host holding project files.
- Known-directory authorization and valid execution trust apply before work; reject
  server registration paths/URIs/symlinks that escape the approved root.
- Do not widen sessions to parents or let server requests request arbitrary contents.
- Keep CD-19 denial of applyEdit/server commands and bounded allowlisted responses.
- Watch notifications and reconciliation requests must fit bounded app/LSP transport;
  sequence gaps require resnapshot/refresh and explicit partial/stale status.
- Push-only diagnostics remain the baseline. Even a reliable disk watch does not
  establish current-draft freshness for unversioned publications after edits.
- Opened-file, unopened-file, saved-file, and uncertain coverage remain distinguishable.
- Do not log/persist bodies, raw events containing source, or diagnostic excerpts.

## Focused tests and manual QA

- Fake timers cover reopen before/after grace, refresh races, delete/recreate,
  external rename, disk edits while dirty, and edits made during reconciliation.
- Watch-supported and no-watch adapters produce honest distinct coverage states.
- Verify hostile registrations, symlink escapes, excessive patterns/events, overflow,
  unregister races, disconnect, and revocation release bounded resources.
- Change a file with another editor/agent while hidden; reopen/refresh and rerun
  without losing a draft or presenting stale ranges as current.

### R01 freshness clarification (2026-10-22)

[Ownership audit and R03 decision](../plan/code-diagnostics-ownership-audit.md):
current-session checking rejects old generations, not old opens of the same URI
at the same version in a reused generation. The current adapter path route can
rebind a delayed v1 finding or empty clear to a reopened v1 document. Freshness
must remain uncertified without isolation; bounded URI ambiguity tracking must
not silently forget reuse. Regression schedules include grace reuse, expiry,
delete/recreate and reattachment. R03/R09/R10 remain unimplemented by R01;
this parent remains partial and progress stays **19/28**.

### R03 URI lifecycle isolation (2026-10-22)
