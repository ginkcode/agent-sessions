- Plan: [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Feed normalized code diagnostics into CodeMirror lint with correct ranges,
cached-tab behavior, and strict saved-file versus dirty-draft freshness guards.

## Grounding in current code

- `frontend/package.json` has CodeMirror state/view/search packages but no `@codemirror/lint`.
- `FileEditor.svelte` lazy-loads the editor runtime and forwards reactive options.
- `fileEditor.ts` caches immutable EditorState by tab object in a WeakMap.
- Cache reuse checks editor version and text; extensions must not capture stale view props.
- Owners are resolved through a WeakMap; wrapping/editing/language use compartments.
- `FileEditState.version` rebuilds editor history caches, not a per-keystroke diagnostic version.
- Draft text is LF-normalized; saved revision and original newline/BOM metadata are separate.

## Concrete steps

1. Add `@codemirror/lint` using the frontend's existing dependency/lockfile workflow.
   Keep the editor and lint runtime lazy; do not put discovery on dialog rendering.
2. Extend editor options with context-bound diagnostic input and freshness identity,
   following CD-01/CD-10 rather than inventing a second draft text owner.
3. Pass those options through FileViewer and FileEditor on every reactive update,
   including results arriving before the lazy import resolves.
4. Add a pure normalized-range-to-CodeMirror-offset converter against the actual
   EditorState document; use UTF-16 columns, zero-based lines, and exclusive ends.
5. Validate malformed/out-of-bounds ranges without crashing; do not manufacture
   lint ranges for file-level findings. Keep those entries in panel/file messages.
6. Publish normalized lint diagnostics with severity, source, optional code, and plain
   message text. Do not attach quick-fix actions, command links, or HTML renderers.
7. Update diagnostics with state effects/compartments without rebuilding editor state,
   changing text, creating undo entries, invoking onchange, or stealing focus.
8. Suppress saved-file markers immediately when draft differs from the checked snapshot.
   Do not rely on CodeMirror's automatic mapped ranges to imply fresh checker results.
9. Gate reapplication by backend/root/attachment generation, tab identity, and saved
   revision/freshness. An undo to baseline alone is not proof of an unchanged disk revision.
10. On cached state restore, clear/reapply the current eligible diagnostic set before
    display; old cached lint state must not survive revocation, empty results, or host switches.
11. Keep cached extensions owner-neutral; avoid closures over prior options/view and
    reject late asynchronous updates after editor destruction or tab replacement.
12. Coordinate exact-range selection/reveal with CD-12 without replacing existing
    line-only blame selection, source position restoration, or prompt focus guards.

## Contract and security considerations

- API names and diagnostic identities remain provisional until CD-01.
- Do not reuse `provider.Diagnostics` / `Backend.Diagnostics()` for this feature.
- Keep editor cache version distinct from monotonic diagnostic-document versions.
- Checker results describe saved files only; no auto-save or draft submission in Stage 1.
- Messages are text; no raw protocol/document-body logging, persistence, or telemetry.
- Only validated in-root findings can reach a tab; no custom shell or server-driven edits.
