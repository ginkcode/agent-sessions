# CD-07 — Code-diagnostics manager and result lifecycle

- **Status:** Done — headless manager, bounded snapshots/events and lifecycle tests
- **Stage:** 1 — Project checks
- **Estimate:** 4 h
- **Dependencies:** CD-01, CD-03
- **Plan:** [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Implement backend ownership of project/provider state, run generations, snapshots,
limits, and stale transitions using finalized [CD-01](CD-01.md) contracts and the
CD-03 supervisor. Use fake adapters so this task does not depend on CD-05/CD-06.

## Current code grounding

- `internal/engine/service.go` holds scanner health in `diag`, `scanErrs`, and
  `states`; none is a code-diagnostics result store or process manager.
- `internal/engine/engine.go` owns lifecycle and an emitter; keep the new package
  headless rather than embedding Wails or RPC transport concerns.
- Existing catalog events are coalesced; diagnostic replacement/sequence semantics
  must not be lost by copying catalog invalidation behavior indiscriminately.

## Concrete implementation steps

1. Implement manager state and injectable adapter registry using CD-01 project,
   attachment, generation, provider/run identity, and trust lifecycle semantics.
   Register production adapters later without requiring them for manager tests.
2. Separate provider availability, execution state, coverage, freshness, and result
   ownership. Support unsupported/missing tools independently for each adapter.
3. Coordinate explicit runs with CD-03, coalescing/superseding under its concurrency
   policy; validate attachment and approval before dispatch and before publication.
4. Atomically replace a provider's checker set only on the CD-01 qualifying outcome,
   including empty success. Retain prior results stale on failure/cancel, handle
   partial outcomes exactly as finalized, and reject old run completions.
5. Maintain explicit clear/invalidation operations for deleted files, revocation,
   detached/invalidated generations, shutdown, and future closed LSP sessions.
   Keep checker/LSP ownership separate without implementing language servers.
6. Implement immutable/deep-copied snapshots and ordered events with sequence and
   generation IDs. Make attach/snapshot reconciliation follow CD-01; never expose
   mutable internal maps or emit while holding locks that call back into manager.
7. Enforce project finding/message/result-byte budgets and bounded event batches.
   Validate the proposed 10,000 findings against serialization/frame overhead;
   report truncation/partial state and a recoverable resnapshot path explicitly.
8. Preserve provider attribution and shared exact-dedup semantics without merging
   unrelated findings. Define deterministic ordering/count projections from the
   contract for consistent downstream panel/tree/marker consumers.
9. Connect CD-02 revoke and supervisor shutdown hooks; invalidate state before
   awaiting cancellation so late process output cannot revive removed results.
   Make detach/cancel/shutdown repeatable and independent of frontend drafts.

## Contract and security considerations

- No reuse of scanner `provider.Diagnostics`, scan diagnostics maps, or events.
- Never trust provider paths/locations; apply shared validation before storing
  findings. Out-of-root findings are status, not navigable paths.
- Store results in memory only; logs/telemetry must not contain diagnostic bodies.
- A run failure is not an empty clean project, and opened-file coverage is not
  project-wide coverage. Saved-file metadata must survive all projections.

## Focused tests

- Fake provider: findings → empty success; findings → fail/cancel; mixed/partial
  result; two providers with independent availability and exact shared findings.
- Races: superseded run finishes last, revoke during completion, detach/reattach,
  generation switch, snapshot concurrent with event, delete during run, shutdown.
- Limits: too many findings, huge messages/escaped JSON, event batch boundaries,
  gap/resnapshot signal, deep-copy isolation, bounded pending work; run race tests.
