## Goal

Show source-view gutter indicators, range highlighting, and plain-text messages
while handling file-level, stale, invalid, and saved-file findings honestly.

## Grounding in current code

- `SourceView.svelte` renders DiffRow indexes against plainLines or highlight.js htmlLines.
- Wrapped rendering uses a grid; unwrapped rendering separates a sticky gutter and text column.
- Gutter buttons select lines and already expose Git change marks and selection state.
- highlight.js output enters `{@html}` only as escaped/tokenized source text.
- `FileViewer.svelte` selects source versus diff, rendered previews, images, and editing mode.
- `fileFind.svelte.ts` and line-click delegation depend on the source DOM structure.

## Concrete steps

1. Consume normalized active-file diagnostics from CD-10 through FileViewer props/selectors.
   Keep process state out of SourceView and the files store.
2. Select only findings whose saved revision/freshness matches displayed source.
   Keep stale findings visible as labeled messages, not apparently current underlines.
3. Build a pure range-to-line/segment projection using zero-based UTF-16 coordinates
   and exclusive ends; handle multiline, zero-width, empty-line, and end-of-file ranges.
4. Validate endpoints against displayed text; reject malformed or unmappable ranges
   without throwing or inventing authoritative coordinates. Retain an explanatory entry.
5. Add severity indicators that coexist with Git change marks and line selection.
   Provide text/icon labels and keyboard access to messages, not color-only signals.
6. Render range highlights over source text without inserting diagnostic text into
   syntax HTML. Preserve highlight.js token styling, escaping, and native text selection.
7. Avoid slicing raw highlight.js markup by diagnostic string offsets; use safe text
   segmentation or non-destructive DOM/decorations with a tested UTF-16 mapping.
8. Expose all messages on a line/range when findings overlap; preserve source,
   optional code, severity, and stale/saved-file labels as ordinary text.
9. Show file-level findings in a file message region without manufacturing line 1 markers.
10. Suppress source-coordinate overlays in Git diff, blame, rendered Markdown, and images.
    Navigation should request source mode rather than annotate those coordinate systems.
11. Preserve wrapped/unwrapped alignment, sticky gutters, presentation font size,
    line-click/Shift-selection behavior, find behavior, and existing source scroll restoration.
12. Clear markers immediately on file/project/host generation invalidation or empty replacement.

## Contract and security considerations

- API and model names remain provisional until CD-01; use CD-10 mocks meanwhile.
- This is code diagnostics, never existing session-parser `provider.Diagnostics`.
- Lines/columns are not byte offsets or visual tab columns; test CRLF and non-BMP Unicode.
- Diagnostic messages must never enter `{@html}`, even though source highlighting already does.
- Do not fetch out-of-root contents, execute message links, log excerpts, or persist findings.
- Saved-file checks cannot decorate dirty drafts as current or trigger implicit saving.
