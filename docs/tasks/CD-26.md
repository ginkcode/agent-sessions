# CD-26 — End-to-end fake-server live diagnostics tests

- Status: Not started
- Stage: 2
- Estimate: 4 h
- Dependencies: CD-21…CD-25
- Plan: [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Prove the live diagnostics lifecycle across the implemented boundaries using a
controllable fake server: Unicode, versions, clearing, crashes, disconnects, limits,
and cleanup. Tests adopt CD-01 contracts; proposed APIs must not be frozen here.

## Current architecture and likely files

- Proposed `internal/codediagnostics/` fake-server executable/helper and integration tests.
- `internal/{engine,app,rpc}/` focused integration and authorization tests.
- `frontend/test/` API/store/editor integration tests using existing Node test setup.
- CD-18 transport fixtures, CD-22…CD-24 adapters, and CD-25 watch fallback fixtures.
- Reuse existing file-editing/RPC test patterns without requiring installed servers.

## Implementation steps

1. Extend the smallest existing fake-server harness to control initialize, sync,
   publication version/order, requests, crash timing, and shutdown behavior.
2. Drive a full approved attachment through open/read/edit/change/save/close,
   snapshot/events, normalization, and frontend freshness consumers.
3. Assert exact range conversions for zero-based UTF-16 exclusive ends with non-BMP
   text, CRLF, multiline/zero-width ranges, and negotiated alternate encoding if supported.
4. Publish current, older, wrong-document, wrong-host/root/generation, and unversioned
   diagnostics; verify only matching snapshots get current inline markers.
5. Publish empty sets and remove/reopen/delete files, verifying provider/document
   replacement without accidentally clearing checker or other server findings.
6. Exercise startup failure, crash mid-request, canceled work, reconnect, backend
   switch, revoke, idle grace, eviction, and app shutdown with late publications.
7. Exercise framing/message/queue/request/document limits and RPC batch limits.
   Verify partial/truncated/stale status and sequence-gap resnapshot behavior.
8. Exercise safe request replies against applyEdit, commands, workspace expansion,
   out-of-root content paths, configuration abuse, and excessive watch registrations.
9. Record process/goroutine/waiter/timer cleanup through deterministic synchronization;
   avoid flaky sleeps and avoid globally destructive process matching.
10. Keep the suite bounded in runtime and independent of tool downloads/network;
    document which real-server/platform behavior remains for CD-27.

## Contract and security considerations

- The fake server imitates push diagnostics; test pull-only capability rejection
  rather than accidentally claiming pull/refresh support.
- Unversioned pushes stay uncertain after edits; no debounce timeout alone proves
  freshness. Saved-file checker findings never become current dirty-draft overlays.
- Assert execution cannot precede known-directory and host/root trust approval.
- Execution remains host-local; RPC carries bounded operations/results, not tunneled LSP.
- Server requests never cause edits, commands, arbitrary file disclosure, or root widening.
- Hostile messages render as plain text; no raw protocol/body persistence or telemetry.
- Include unauthorized paths, revoked grants, generation races, and stderr sanitization.
- Verify external-watch absence/overflow marks unopened-file coverage stale explicitly.

## Focused tests and manual QA

- Run relevant Go package tests and frontend tests with no real language server installed.
- Run Go race detection on touched concurrent manager/transport/RPC paths where supported.
- Repeat lifecycle/race cases deterministically to detect duplicate sessions and leaks.
- Inspect one fake-server UI smoke flow for panel/count/marker agreement, accessible
  messages, stale/partial labels, draft retention, and intact undo state.
- Tests should use sanitized source fixtures, not captured private project bodies.

## Acceptance checklist

- [ ] End-to-end tests cover Unicode, version uncertainty, empty clears, and ownership.
- [ ] Crashes/disconnects/revocation cannot repopulate invalidated projects or lose drafts.
- [ ] Limits and unsafe server requests have bounded, observable, safe outcomes.
- [ ] Repeated lifecycle tests leave no owned processes, waiters, timers, or watchers.
- [ ] Test coverage and real-server/platform gaps are documented for CD-27.

## Out of scope

Building a general LSP conformance suite, benchmarking all servers, real-server version
support expansion, platform QA sign-off, and implementation of unrelated IDE features.
