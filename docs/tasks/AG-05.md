# AG-05 — Terminal attention signals

- Status: ✅ Done (2026-10-24)
- Estimate: 3 h
- Dependencies: AG-03, AG-04
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Give every agent tab one clear state: **working**, **needs you** (waiting for
approval or input), **done** (turn finished) or **exited**.

## Design

- The terminal view reports per tab: output activity (time of the last
  output), BEL, OSC 9 and OSC 777 `notify` sequences (with their text), and
  exit.
- A pure `agentAttention(tab, session)` combines them:
  - exited → `exited`;
  - output in the last 1.5 s → `working`;
  - a bell or notification since the user last looked at the tab → `needs`;
  - quiet output and session `Turn` is `tool` → `needs`;
  - quiet output and `Turn` is `done` → `done`;
  - otherwise the last known state.
  Input typed into the tab clears `needs` and `done`.
- Agents that are told to notify through the terminal (Claude Code's
  `terminal_bell` notification channel, Codex `notify` with OSC 9) give the
  quickest signal; the transcript state covers the others.
- A tab the user is looking at (panel open, tab active, window focused) never
  becomes `needs` or `done` for alerting, only for its own indicator.

## Done when

- Unit tests over `agentAttention` cover every rule and their order, and the
  OSC parsing covers BEL inside OSC sequences (which is a terminator, not a
  bell).

## Outcome

- `src/lib/attention.ts`:
  - `agentAttention(facts, now)` is pure. In order:
    1. exited;
    2. the agent's own output in the last 1.5 s → working;
    3. a bell or notification the user hasn't seen or typed past → needs;
    4. a session report that arrived after the user's last input, and after
       the agent worked since that input, with turn `tool` → needs, `done` →
       done, `working` → working;
    5. anything else → **idle**.
  - Change from the plan: the fallback is idle, not "the last known state".
    A quiet tab with no fresh evidence shows nothing, rather than a stale
    "working" (an unlinked tab would otherwise stay working forever).
    "Reported after the input and the work" keeps two false alerts out:
    - a resumed session reading `done` before anything happened;
    - an old `done` showing while a new prompt starts.
  - `TerminalSignalScanner` finds BEL, OSC 9 and OSC 777 `notify` in raw
    output, across chunk boundaries and split UTF-8:
    - A BEL or ESC that ends an OSC is a terminator, not a bell.
    - A BEL inside DCS, SOS, PM or APC is part of the string.
    - CAN and SUB cancel a sequence.
    - OSC 9 payloads that are ConEmu commands (`9;4;…` progress and the
      like) are not notifications.
    - A chunk holding only signals doesn't count as drawing.
  - `isUserInput` sets the terminal's own replies apart from what the user
    typed. Replies are focus reports, cursor position, device attributes,
    DSR, DECRPM, window reports, and OSC or DCS replies. Replies neither
    clear needs/done nor count as input.
  - `AttentionTracker` applies the rules per tab, with a timer for when
    output goes quiet. Output within 250 ms of input or a resize is an echo
    or redraw, not work. A tab started with a prompt (a handoff) counts its
    start as input.
- `TerminalsStore`:
  - follows agent tabs only (`attention[id]`), from all output, including
    tabs whose view isn't mounted;
  - follows input (`write`), exits and resizes (`TerminalView.sendSize`);
  - tracks which tab the user is looking at: the panel is open, the tab is
    active and the window has focus. Bells while looking don't count, and
    starting to look clears them.
  - `sessionReported` replaces `renameSession`: a catalog change for a
    linked session renames its tabs and passes them its turn. A turn known
    only from linking doesn't count as a report.
- The dev mock (`npm run dev`) simulates agent turns:
  - a spinner for 2.4 s, then the answer, with the session's turn going
    `working` → `done`;
  - a prompt containing "approve" ends in an approval question, a bell and
    the turn `tool`.
  Tests keep the instant mock.
- Tests:
  - `test/attention.test.mjs`: rule order, freshness, scanner, notification
    payloads, terminal replies, tracker flows (echo, quiet timer,
    approvals, bells while looked at, handoff, exit, resize).
  - `test/session-links.test.mjs`: the store's looking rule, shells not
    followed, window focus, and an end-to-end mock turn ending in needs.
- Showing these states is AG-06.
- Manual check still needed: whether real agents' idle screens stay quiet
  (no redraws while waiting). If an agent redraws on its own, it reads as
  working until it stops.
