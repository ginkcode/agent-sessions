## Contract and security considerations

- Confirm actual process location: local/SSH/WSL uses the host holding the project,
  with that host's installed tools; no local copy or frontend LSP tunnel.
- Directory authorization differs from execution trust; plugins/config can execute,
  caches/network may be used, and approval must not claim sandboxing.
- Verify fixed executable execution with no installation/download/package-script fallback.
- Check safe denial of applyEdit/commands/out-of-root expansion using existing fake
  tests; do not use destructive real-server probes against user projects.
- Verify bounded LSP/app transport and sanitized errors without recording raw bodies,
  protocol traffic, or secret-bearing diagnostics in QA evidence.
- Push-only support, unversioned freshness uncertainty, opened-file coverage, and
  missing file-watch stale fallback must be visible documented limitations.
- An empty report is “No reported problems,” not proof all project files are clean.
