- **Status:** Done

## Goal

Establish the authoritative contract that CD-02 onward implement. Resolve the
plan's provisional names and semantics in a versioned contract document and JSON
fixtures before wiring production behavior. Code diagnostics must remain separate
from session-parser health (`provider.Diagnostics` and `Backend.Diagnostics()`).

## Current code grounding

- `internal/engine/backend.go` is context-first; both Engine and RPC implement it.
- `internal/engine/service.go` owns scanner diagnostics and `knownDirectory`.
- `internal/rpc/types.go` has optional capabilities; framing is newline JSON with
  a 64 MiB frame cap, not LSP Content-Length framing.
- `frontend/src/lib/link.ts` guards replies by connection epoch; the files store
  separately owns drafts, revisions, cached tabs, and editor history versions.

## Concrete implementation steps

1. Write a dedicated contract reference linked to the plan; distinguish settled
   requirements, decisions made here, and deferred tool-specific evidence.
2. Specify host/connection identity plus canonical authorized root, opaque
   attachment token, generation, run ID, sequence, document version, and saved
   revision. Define serialization and numeric limits safe in Go and JavaScript.
3. Specify normalized path, optional range, four severities, text message, source,
   optional code, provider ID, checker/LSP origin, and freshness/coverage metadata.
   Use zero-based UTF-16 columns and exclusive ends; define invalid-range handling.
4. Define provider-owned replacement: successful checker runs replace atomically,
   including empty sets; failure/cancel preserves stale prior sets; LSP replaces
   one document, including empty publications. Define explicit clearing rules.
5. Define exact-equivalence deduplication and retained source attribution; counts
   default to errors/warnings. Similar messages must remain separate findings.
6. Finalize operation/event names, request/response/error shapes, and ownership:
   attach/detach, snapshot, approve/revoke, run/cancel, and future document sync.
   Reserve Stage 2 shapes without claiming live support in Stage 1.
7. Specify attach/snapshot/event ordering, bounded batches, atomic assembly,
   sequence-gap recovery, truncation, and resnapshot. Define availability, run,
   freshness, and coverage states without collapsing them into one success flag.
8. Specify stale-publication rejection and lifecycle rules for reconnect, revoke,
   restart, replacement, deletion, close, and backend switch. Separate future
   didSave coordination from a second document-text owner.
9. Commit representative JSON fixtures and a race-case matrix; document which
   layer validates paths, identity, bounds, and trust. Link downstream tasks here.

## Contract and security considerations

- Root discovery stays inside the authorized root; no implicit parent expansion.
- Directory authorization is not execution approval; tokens are connection-scoped.
- Results stay in memory; messages are untrusted text and may contain secrets.
- Confirm byte budgets against JSON escaping, envelopes, and RPC frame limits.

## Focused tests

- Fixture validation/round-trip cases: absent range, empty replacement, all
  severities, Unicode/non-BMP, CRLF, stale saved revision, and multiple sources.
- Specify executable race assertions for newer event before snapshot, old run
  after retry, reconnect on same path, revoke during execution, and sequence gaps.
