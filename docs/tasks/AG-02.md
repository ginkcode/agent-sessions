# AG-02 — New session entry points

- Status: ✅ Done (2026-10-24)
- Estimate: 3 h
- Dependencies: AG-01
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Starting an agent is one click from wherever the user is looking at a project.

## Design

- **Session list:** a directory group's context menu gets "New Claude Code
  session", "New Codex session" and "New OpenCode session", showing only
  agents that are installed on the host (detection already knows which are
  present).
- **Session header:** a "New session" split button next to Resume: the main
  part starts the same agent in the session's directory, the menu offers the
  other agents.
- **Go to File:** the header's project name menu gets the same entries.
- **Keyboard:** Cmd/Ctrl+Shift+N starts the last used agent in the current
  project (the selected session's directory, or the Go to File project).
- The last used agent is remembered in preferences.
- Launch failures show the existing toast with the install hint. Hidden on
  hosts without the `newSession` capability.

## Done when

- Server-render tests cover the menus, the split button, hidden entries for
  agents not installed and for old servers.
- Manual check still needed: the panel opening and focusing the new tab.

## Outcome

- **Availability is real, and shown rather than hidden.** Nothing knew which
  agent CLIs were installed (detection finds session files, not binaries), so
  the host now reports it: `newSessionAgents` (Go `Service.NewSessionAgents`)
  looks each CLI up with `launch.Find`, the same lookup a launch makes, on
  this computer or on the WSL/SSH host's server. Missing agents stay listed
  but disabled, with the install hint as their tooltip, so the menus say what
  to install instead of silently dropping an agent. Until a report arrives
  every agent is offered and a failed launch toasts the hint.
- **Session list:** a directory's ⋯/right-click menu ends with "New Claude
  Code Session", "New Codex Session" and "New OpenCode Session"; all disabled
  with a reason when the directory is gone.
- **Session header:** a "New ▾" split before "Continue in": New starts the
  session's agent in its directory (disabled with the hint when that agent is
  missing), ▾ lists every agent.
- **Go to File:** the project root's menu (the project name button and blank
  space) starts with the new-session entries. Subdirectories do not offer
  them: the backend only starts sessions in a known project directory. When
  the session opens in the panel, which sits behind the dialog, the dialog
  closes.
- **Keyboard:** ⌘⇧A on macOS, Ctrl+Shift+A elsewhere, not Cmd/Ctrl+Shift+N,
  which is already New window on Windows and Linux. It starts the last used
  agent (or the first installed one) in the selected session's directory, or
  in the Go to File project while that is open. The terminal panel passes it
  through to the app.
- The last used agent is kept in localStorage
  (`agent-sessions:new-session-agent`), like the app's other UI choices.
- New sessions open where agents open (panel or external terminal); a host
  only the panel can reach uses the panel. Everything is hidden without the
  `newSession` capability.
- Tests: `test/new-session.test.mjs` (choices, menu items, shortcut, mock,
  header split incl. missing agent and missing directory, store routing and
  per-host reports), Go `TestNewSessionAgents`, app/rpc launcher tests.
- Manual check still needed: the panel opening and focusing the new tab, and
  the dialog closing for it.
