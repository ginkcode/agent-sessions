# PS-04 — Replace engine

- Status: ✅ Done (2026-10-24)
- Estimate: 3 h
- Dependencies: PS-01
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Replace matches in files on disk safely: never over a newer file, never in a
protected file, keeping each file's encoding.

## Design

- `files.Replace(ctx, root, policy, req ReplaceRequest) ReplaceResult`.
  `ReplaceRequest`: the `SearchQuery`, `Replacement`, and per file the path,
  the expected revision, and optionally the matches to replace (line and
  UTF-16 start). Without a match list, every match in the file is replaced.
- Regex replacements expand `$1` and `${name}` like Go's `Regexp.Expand`;
  literal replacements are taken as they are.
- Each file goes through the save path: `EditPolicy` check, the edit size
  limit, revision check, BOM and line endings kept. The replacement is
  computed on the decoded text with LF endings, so a match never spans the
  CR of a CRLF.
- Per-file outcome: `replaced` (count and new revision), `conflict` (file
  changed since the search), `skipped` (protected, too large, not text, or a
  selected match no longer matches), or `failed` (message). One file's
  failure does not stop the rest.
- `engine`, `rpc` (method `replaceInFiles`, capability `ReplaceFiles`, sent
  only by servers that can save) and app binding `ReplaceInFiles`.

## Done when

- Tests cover full and selected-match replace, `$1` expansion, CRLF and BOM
  files, conflict after an outside change, protected paths, a stale match
  selection, and continued processing after one failure.
- RPC and app tests cover routing and the capability flag.
