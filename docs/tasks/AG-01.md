# AG-01 — New session launch

- Status: ⬜ Not started
- Estimate: 4 h
- Dependencies: none
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Start a fresh Claude Code, Codex or OpenCode session in a project directory,
on local, WSL and SSH hosts, in the built-in panel or an external terminal.

## Design

- `provider.Provider` gains `NewSessionCommand(dir string) Command`: `claude`,
  `codex` and `opencode`, each run in `dir`. All three providers implement it.
- `Service.NewSessionLaunch(agent, dir)` checks `knownDirectory`, so sessions
  start only in projects the catalog knows, and returns the command.
- Panel: `App.PanelNewSession(agent, dir, size)` builds the command and uses
  `startPanelAgent`, like `PanelResume`. Remote hosts get the script from the
  server through a new RPC method `newSessionTerminalScript` (capability
  `NewSession`), so the agent is found on that host with its login shell
  environment, as resume does.
- External: `App.OpenNewSessionInTerminal(agent, dir)` through
  `openInTerminal` (local and WSL; SSH stays panel-only as with resume).
- A missing agent returns `ErrAgentNotFound` with the install hint.
- The tab label is the agent's name and the tab records agent, host, dir and
  start time for AG-03.

## Done when

- Provider tests cover each command; service tests cover unknown directories;
  launch tests cover the panel argv for local, WSL and SSH scripts; RPC tests
  cover the new method and capability.
