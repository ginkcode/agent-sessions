# PS-01 — Content search engine

- Status: ✅ Done (2026-10-24)
- Estimate: 4 h
- Dependencies: none
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Search the text of every project file on the host, quickly and with bounded
cost, so the Search pane can show matches across the project.

## Design

- New `internal/files/search.go`: `Search(ctx, root string, q SearchQuery) (SearchResult, error)`.
- `SearchQuery`: `Pattern`, `Regex`, `MatchCase`, `WholeWord`, `Include` and
  `Exclude` (comma-separated globs such as `*.go, src/**`), `MaxMatches`.
- File set: the same as `List`: `git ls-files --cached --others
  --exclude-standard` inside Git (ignored files skipped), the walk with
  `skipDirs` outside Git. Symbolic links are not followed outside the root.
- Skip files larger than `MaxReadBytes`, binary files (NUL in the first 8 KB)
  and files that are not valid UTF-8.
- Literal search is a quoted regex, so one RE2 path serves both. Whole word
  wraps the pattern in `\b` when its ends are word characters. Without match
  case the pattern gets `(?i)`.
- Workers: `min(GOMAXPROCS, 8)` read and scan files; results are sorted by
  path so the order is stable.
- Each match reports line number (1-based), start and end in UTF-16 code
  units (the unit the frontend and LSP use), and a preview of the line capped
  at 240 characters around the match, with offsets into the preview.
- Each file reports its revision (`revisionOf`) so replace can check it later.
- Bounds: `MaxMatches` default 5,000 and at most 20,000; 1,000 matches per file;
  the result says `Truncated` when either cap cut it short. The context is
  checked between files, so cancel returns quickly.
- An invalid regex returns `ErrInvalidPattern` with RE2's message.

## Done when

- Table tests cover literal, regex, match case, whole word, include and
  exclude globs, ignored files, binary and oversized files, non-UTF-8 files,
  multi-byte and astral characters (UTF-16 columns), CRLF lines, truncation,
  cancellation and invalid patterns.
- A benchmark over a generated 5,000-file tree runs in well under a second.
