# CD-08 — Engine and App code-diagnostics bindings

- **Status:** ✅ Done
- **Stage:** 1 — Project checks
- **Estimate:** 3 h
- **Dependencies:** CD-02, CD-07
- **Plan:** [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Route Stage 1 code-diagnostics operations through Engine and App with known-root
and trust enforcement, correct backend selection, offline errors, and shutdown.
Follow finalized [CD-01](CD-01.md); do not invent independent operation names.

## Current code grounding

- `internal/engine/backend.go` is implemented by Engine, RPC Client, and
  `internal/app/offline.go`; adding methods requires keeping these builds coherent.
- `internal/app/service.go` aliases engine.Service; authorization belongs in the
  headless engine/service layer, not only in a Wails wrapper.
- `connection.backend` in `internal/app/remote.go` selects the active backend;
  offlineBackend intentionally fails rather than falling back to Local.
- `internal/app/events.go` adapts engine emitters to Wails events.

## Concrete implementation steps

1. Adopt CD-01 signatures and decide whether the finalized design extends Backend
   directly or uses a negotiated optional surface. Inventory every implementation,
   mock, and compile-time assertion before changing the interface.
2. Add context-first engine/service operations for attach/detach, snapshot,
   approve/revoke, explicit run/cancel, and any finalized Stage 1 retry semantics.
   Do not enable document-sync execution merely because CD-01 reserves its types.
3. Authorize catalog-known directory before canonicalization/discovery/execution;
   bind root identity to the caller's attachment and recheck approval/fingerprint
   at execution boundaries. A client-supplied token/root is not authorization.
4. Construct/own CD-07 manager and CD-02 grants in engine lifecycle. Keep discovery
   asynchronous; attach must not block dialog rendering on tool process startup.
5. Add App/Wails wrappers using the selected backend and request context, with
   stale-connection/host safeguards equivalent to existing file-mutation routing.
   Never execute a selected remote project against Local during disconnect.
6. Forward bounded scoped events through the existing emitter abstraction, with
   owner/connection generation checks before Wails delivery. Ensure unsubscribe,
   backend replacement, revocation, and app shutdown invalidate old publications.
7. Add offline behavior for every new operation using the existing disconnected
   error conventions; preserve browsing/editing behavior and retained drafts.
8. Keep intermediate builds coherent before CD-09 implements RPC: if Backend is
   extended, add only the minimal explicit unsupported remote conformance methods
   and test-double updates required, documenting CD-09 replacement ownership.
9. Regenerate Wails bindings by the repository's existing workflow if needed;
   do not hand-maintain generated output or implement frontend controls here.

## Likely files

- `internal/engine/{backend,service,engine}.go`, a focused code-diagnostics file,
  and corresponding authorization/lifecycle tests.
- `internal/app/` code-diagnostics wrappers, `offline.go`, `events.go`, `app.go`,
  and remote routing/shutdown tests as required by actual ownership.
- Existing Backend test doubles; `internal/rpc/client.go` only for necessary
  temporary conformance, not full RPC behavior before CD-09.
- Generated frontend Wails bindings if the build workflow requires regeneration.

## Contract and security considerations

- Keep `Diagnostics()`/`GetDiagnostics` and provider parser health unchanged.
- Authorization/trust must be enforced server-side for every entry path, not
  merely disabled UI controls. No source/output bodies in logs or persistence.
- Cancellation must target the owning attachment/run, not another caller's work.
- Avoid waiting for processes or invoking callbacks while engine locks are held.

## Focused tests

- Known/unknown CWD and RepoRoot, nested-root containment, approval required,
  fingerprint mismatch, revoked token, foreign attachment, and canceled context.
- Local routing, selected remote offline failure, backend switch mid-request,
  stale event suppression, repeated shutdown, and cancellation cleanup.
- Compile/test all Backend implementations and existing provider diagnostics.
