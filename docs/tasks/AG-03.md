# AG-03 — Link terminal tabs to sessions

- Status: ✅ Done (2026-10-24)
- Estimate: 3 h
- Dependencies: AG-01
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Every agent tab knows which session it is running, so tabs show the session
title, the transcript can show "running in terminal", and alerts can point at
both.

## Design

- Resume tabs know their session from the start. New-session tabs record
  agent, host, directory and start time, and link to the first session of
  that agent and host whose directory matches and that was created after the
  start (with a 5 s allowance for clock rounding), seen in `catalog:changed`
  or a catalog refresh. A session already linked to another tab is skipped,
  so two new tabs in the same directory link in start order.
- Linked tabs show the session title (shortened) and an agent icon. Clicking
  the tab's title menu offers "Show transcript".
- The session header shows "Running in terminal" with a button that focuses
  that tab, instead of starting a second copy; Resume still offers a new tab
  through its menu.
- Links end when the tab closes.

## Done when

- Store tests cover linking order, the time allowance, two tabs in one
  directory, remote host matching and unlinking on close.
- Server-render tests cover the tab label and the header state.

## Outcome

- **Linking.** Resume tabs carry their session from the start. New-session
  and handoff tabs (both start a fresh session) wait with `linkPending`; the
  `sessionLinks` store watches `catalog:changed` and, when a change may hold
  one of their agents' sessions, lists that agent's sessions in the tab's
  directory (`listSessions` with agent and path, oldest first) and pairs
  them with `matchNewSessions`: each tab, in start order, takes the earliest
  top-level session created after it started less 5 s, that no tab of the
  host already runs. Directories compare as written, less trailing
  separators.
- Only the shown host's catalog is visible, so tabs of another host link
  when it is shown again (its catalog rebuild is a full refresh). Linked
  tabs follow renames and are unlinked, still running, when their session
  is removed. The link ends with the tab.
- Limitation: two new tabs in one directory link in start order even if the
  second is prompted first; the transcript then opens the other tab's
  session until both have saved. Telling them apart would need the agent's
  process to report its session id.
- **Tab label and menu.** A linked tab is named after its session (agent
  icon as before). Its context menu starts with "Show Transcript", disabled
  with the reason until the agent saves the session or while another host is
  shown.
- **Session header.** A running session shows "● Running in terminal" and
  its main button becomes "Show terminal", which selects the tab and opens
  the panel; Resume's menu adds "Resume in a new tab".
- The mock saves a new tab's session when its first prompt is typed, so the
  link can be tried in `npm run dev`.
- Tests: `test/session-links.test.mjs` (matching order, allowance, two tabs
  in one directory, subagents, directory forms, which changes are looked at,
  store linking with the mock incl. other hosts, renames and removal, header
  state).
- Manual check still needed: a real agent's first save linking the tab.
