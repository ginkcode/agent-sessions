# AG-04 — Turn state from session files

- Status: ⬜ Not started
- Estimate: 4 h
- Dependencies: none
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Know from the session files whether an agent's last turn finished or stopped
at a tool call that has no result yet, for every provider.

## Design

- `model.SessionMeta.Turn`: `""` (unknown), `working`, `done` or `tool`
  (a tool call without a result yet, which is how an approval prompt looks on
  disk). Set by each scanner from the last relevant record, so incremental
  scans keep it current:
  - Claude: assistant `stop_reason: end_turn` → `done`; an assistant
    `tool_use` whose `tool_result` has not followed → `tool`; a user prompt or
    tool result → `working`.
  - Codex: `event_msg` `task_complete`/`turn_complete`/`turn_aborted` →
    `done`; `task_started` or a response item → `working`; a function call
    without its output → `tool`.
  - OpenCode: assistant message with `finish` set and no pending tool →
    `done`; a tool part `pending`/`running` → `tool`; otherwise `working`.
- Claude `sessions/<pid>.json` changes (`busy`↔`idle`) emit `catalog:changed`
  for the affected session even when no transcript changed, so the live
  status and turn state reach the UI within the watcher's debounce.
- The cache index stores `Turn` with the rest of the metadata (schema bump).

## Done when

- Scanner tests per provider cover each state, including incremental scans
  that move from `tool` to `working` to `done`.
- A watcher test covers the status-only catalog event.
