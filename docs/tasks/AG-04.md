# AG-04 — Turn state from session files

- Status: ✅ Done (2026-10-24)
- Estimate: 4 h
- Dependencies: none
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

Know from the session files whether an agent's last turn finished or stopped
at a tool call that has no result yet, for every provider.

## Design

- `model.SessionMeta.Turn`: `""` (unknown), `working`, `done` or `tool`
  (a tool call without a result yet, which is how an approval prompt looks on
  disk). Set by each scanner from the last relevant record, so incremental
  scans keep it current:
  - Claude: assistant `stop_reason: end_turn` → `done`; an assistant
    `tool_use` whose `tool_result` has not followed → `tool`; a user prompt or
    tool result → `working`.
  - Codex: `event_msg` `task_complete`/`turn_complete`/`turn_aborted` →
    `done`; `task_started` or a response item → `working`; a function call
    without its output → `tool`.
  - OpenCode: assistant message with `finish` set and no pending tool →
    `done`; a tool part `pending`/`running` → `tool`; otherwise `working`.
- Claude `sessions/<pid>.json` changes (`busy`↔`idle`) emit `catalog:changed`
  for the affected session even when no transcript changed, so the live
  status and turn state reach the UI within the watcher's debounce.
- The cache index stores `Turn` with the rest of the metadata (schema bump).

## Done when

- Scanner tests per provider cover each state, including incremental scans
  that move from `tool` to `working` to `done`.
- A watcher test covers the status-only catalog event.

## Outcome

- `model.SessionMeta.Turn` (`working`, `done`, `tool`, or empty when
  unknown) is set by each scanner as it reads records, so incremental scans
  keep it current. The checkpoints keep the calls still waiting for a
  result. The index already stores the metadata as JSON, so its schema is
  unchanged. Instead, the Claude (v5), Codex (v4) and OpenCode (v5)
  checkpoint versions were bumped, which rescans every session once to fill
  the field in.
- **Claude.** These rules skip sidechain records:
  - A prompt means `working`.
  - "[Request interrupted by user" or an API error means `done`.
  - A `tool_use` stays pending until its `tool_result` arrives. While any
    call is pending the turn is `tool`.
  - Otherwise, an assistant record ending with `end_turn`, `stop_sequence`,
    `max_tokens` or `refusal` means `done`, and any other stop reason means
    `working`.
  - Older records have no stop reason. Those count as `done` when their
    last part is text and `working` otherwise. In streamed transcripts, a
    text part between tool calls can therefore read as `done` until the next
    record; AG-05's terminal output rule covers that gap.
- **Codex.**
  - `task_started` and conversational user messages mean `working`.
  - `task_complete`, `turn_complete`, `turn_aborted` and `error` mean `done`.
  - A function, custom tool or local shell call stays pending until its output
    arrives, and the turn is `tool` while it waits. A web search does not
    count as pending.
  - Older rollouts have no task events. In those, an assistant message with
    nothing pending means `done`.
- **OpenCode.** Turn comes from the last user or assistant message (v1), or
  the last user, assistant or idle message (v2):
  - A prompt means `working`.
  - `idle` means `done`.
  - An assistant message with a tool part in `pending` or `running` means
    `tool`.
  - An assistant message that failed, or finished for any reason other than
    `tool-calls` or `unknown`, means `done`.
  - Limitation: OpenCode sessions rescan when their `time_updated`
    changes. If OpenCode does not bump it while a tool runs, the state can
    lag until the next update.
- **Badge-only catalog events.** `scan.ApplyLive` returns the sessions whose
  live badge or status changed without a scan change. `index.Refresh`
  reports these as changes, including when no file changed. So a Claude
  `sessions/<pid>.json` going `busy`↔`idle`, or a process exiting, reaches
  the UI within the watcher's debounce.
- Frontend: `SessionMeta.turn` is typed (`SessionTurn`). Showing it is
  AG-05 and AG-06.
- Tests:
  - Claude `TestScanTurnState`: a table of each state, plus incremental
    appends moving tool → working → done.
  - Codex `TestScan_TurnState`: the same, with task events and without.
  - OpenCode `TestLastMessageTurn`, `TestScanV1Turns` and
    `TestScanV2Turns`.
  - Index `TestRefreshLiveOnlyChange`: a status change with no file change,
    a steady status, an exit, and a failing detector.
  - The golden files now include `turn`.
