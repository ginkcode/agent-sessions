# CD-21 — Frontend diagnostic document lifecycle bridge

- Status: Not started
- Stage: 2
- Estimate: 4 h
- Dependencies: CD-15, CD-20
- Plan: [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Bridge read/edit/save/discard/reload/rename/delete/close into versioned live document
operations while leaving tabs, drafts, revisions, and undo state with the files
store. API names and event shapes remain provisional until CD-01 is finalized.

## Current architecture and likely files

- `frontend/src/lib/stores/files.svelte.ts` lifecycle hooks and focused tests.
- Proposed `frontend/src/lib/stores/codeDiagnostics.svelte.ts` bridge/state.
- `frontend/src/lib/{api,types,fileEditor}.ts` and frontend test fixtures.
- `frontend/src/lib/components/common/GoToFileDialog.svelte` attach/hide hooks.
- `.../go-to-file/{FileViewer,SourceView,FileEditor}.svelte` freshness consumers.
- FilesStore already retains hidden drafts and guards uncertain saves/host switches;
  its edit.version resets editor caches and is not automatically an LSP version.

## Implementation steps

1. Define explicit lifecycle hooks from successful files-store transitions rather
   than inferring text changes from DOM/editor mounts or diagnostic state.
2. On displayed read-only or edited document open, send actual displayed text.
   Share one server document across view/editor switches and cached-tab remounts.
3. Maintain monotonic diagnostic versions within the valid attachment/document
   lifecycle, independently of editor cache versions and asynchronous read tokens.
4. Debounce draft changes (proposed 300 ms); honor full/incremental sync negotiated
   by the backend. Invalidate old ranges immediately, before the debounce expires.
5. Flush/order current changes before a successful save's didSave. Preserve later
   typing, and do not acknowledge disk state after failed/uncertain save outcomes.
6. On discard/reload, publish the resulting displayed text only after the files
   store commits that transition; never overwrite a draft to satisfy diagnostics.
7. Map confirmed rename/delete to old-document close and valid new-document open
   or clear. Unknown operation outcomes remain uncertain until reconciled.
8. Close on actual tab removal, including preview replacement and guarded close.
   Account for retained tabs and hide grace without sending duplicate opens.
9. Cancel pending timers/requests on attachment replacement, revocation, disconnect,
   or resolved host switch; reopen valid documents after explicit reconciliation.
10. Consume matching versioned push results; keep unversioned results uncertain and
    separately labeled, never reuse stale underlines after typing.

## Contract and security considerations

- The separate diagnostics store owns protocol state, not user text or save policy.
- Host/root/token/generation guard all asynchronous work, including delayed timers.
- No execution before authorization/approval; servers stay on the project host.
- Use bounded CD-20 transport; surface failed synchronization/oversize text and do
  not silently skip changes while presenting fresh results.
- Never persist/log bodies or send them to external services for this feature.
- Safe server-request denial remains backend-owned; frontend must not execute
  server commands, apply edits, or accept arbitrary requested workspace folders.
- Push-only live coverage means opened documents, not hidden opening of every file.
- Saved-file checker ranges remain in the panel, not over dirty drafts; previews
  such as diff, blame, rendered Markdown, and images get no source overlays.

## Focused tests and manual QA

- Mock API records exact open/change/save/close order with fake debounce timers.
- Read-only open, edit toggle, fast typing, cached tabs, preview replacement, guarded
  close, and hide/reopen retain draft/selection/undo state without duplicate sessions.
- Save races, uncertain saves, discard/reload, confirmed/uncertain rename/delete,
  late reads, host switches, and reconnect cannot publish against the wrong text.
- Unicode/CRLF versions and empty/unversioned/late results exercise marker guards.

## Acceptance checklist

- [ ] Every committed lifecycle transition reconciles the corresponding live document.
- [ ] Drafts and editor caches survive diagnostics updates and lifecycle failures.
- [ ] Debounced updates are bounded, versioned, ordered, and canceled when invalid.
- [ ] Uncertain/stale publications cannot appear as verified current-draft ranges.

## Out of scope

Server adapters, a second text store, hidden full-project didOpen, automatic saves,
completion, formatting, quick fixes, and expanding existing tab/close-guard behavior.
