## Goal

Add a collapsible Problems panel grouped by file, with severity filtering,
keyboard access, and navigation to ranges without losing drafts or tab state.

## Grounding in current code

- `GoToFileDialog.svelte` lays out FilePicker and FileViewer in a flex body.
- `files.openFile(path, { keep, read })` owns preview/kept-tab selection and loading.
- `FileViewer.svelte` tracks line selections and source positions by tab identity.
- Existing `FileLineSelection` is one-based and line-only; it cannot represent diagnostic columns.
- Markdown links already defer navigation until content renders, but only target headings.
- `fileActions` owns destructive close/host-switch guards; diagnostics must not bypass them.

## Concrete steps

1. Add a focused ProblemsPanel component consuming the CD-10 normalized selectors.
2. Integrate a collapsible region in the dialog without remounting the viewer or editor.
3. Group by project-relative file path; use stable ordering within groups and document
   tie-breaking by severity/location/message so event arrival does not shuffle focus.
4. Render severity text/icon, plain-text message, source attribution, optional code,
   and human-readable one-based location. Include file-level findings without a location.
5. Add severity filters for error/warning/information/hint and clear filtered-empty copy.
   Filters affect panel visibility, not global project or badge counts.
6. Provide keyboard-operable group toggles, row activation, and next/previous problem actions.
   Define wraparound and filtered-set behavior; maintain focus if a finding disappears.
7. Add a diagnostic navigation request carrying context, tab/path, range, freshness,
   and a request identity. Names/shapes are provisional pending CD-01.
8. Open or reuse a kept tab through the files store; never replace a dirty draft,
   force a reload, auto-save, close tabs, or directly mutate the editor text.
9. Wait for the matching file load/render, then select and reveal the exact range.
   Reject pending navigation after host/root/generation changes or a newer navigation.
10. Switch rendered Markdown/diff/other previews to source before revealing a location;
    do not place source coordinates on blame, images, or rendered content.
11. For stale saved-file ranges over a dirty draft, open the file but do not select
    misleading coordinates; explain saved-file/stale context. Keep the panel entry visible.
12. For file-level findings, select the file without inventing a line/column range.
    Explain unreadable/deleted targets without destructive fallback actions.

## Contract and security considerations

- Use CD-01 contracts and CD-10 mock/store data; APIs remain provisional until CD-01.
- This feature must not use session-parser `provider.Diagnostics` or `Backend.Diagnostics()`.
- Accept only authorized project-relative paths, not diagnostic-supplied URLs or arbitrary file URIs.
- Range coordinates are zero-based UTF-16 with exclusive ends; display conversion happens at the edge.
- Shared exact deduplication preserves all source attribution; do not merge merely similar messages.
- Messages/codes/paths render as text; no HTML, command links, source fixes, or automatic telemetry.

## Completion evidence

- Shared `ProblemsPanel.svelte` consumes normalized exact-deduplicated findings,
  preserves all source/provider attribution, groups by relative path and orders
  by path/severity/start/end/message/code (not arrival order). Native buttons and
  checkboxes support activation/filter/collapse; scoped Up/Down plus previous/next
  wrap the filtered set including collapsed groups. Removed/filtered focused rows
  fall back to a surviving row or toggle. Filtering never changes global counts.
- The panel is a sibling below the existing dialog body: collapse/filter do not
  remount FileViewer or FileEditor. Hostile messages/codes/paths are plain text;
  invalid absolute, URI, traversal and backslash targets are rejected.
- Viewer requests carry monotonically increasing identity, captured host/root,
  connection version, diagnostics attachment/generation/status, tab object and path.
  Matching load, source mode and post-render tick are guarded again; late reads,
  newer requests, context switches and tab switches cannot reveal old coordinates.
  Markdown/SVG and diff switch to source; highlights settle before text selection.
- Separate UTF-16 range helpers validate exclusive multiline endpoints, CRLF and
  non-BMP boundaries, walk highlighted source text without counting gutters, and
  dispatch exact CodeMirror selection/scroll without document/history changes.
  Existing one-based line-only blame selection is unchanged. Lazy editor reveal
  also rechecks identity/freshness at mount. No save/reload/close/host-switch bypass.
- Kept-tab opening reuses the files store, preserving dirty previews and drafts.
  Dirty, uncertain, conflicted, stale or revision-unverified saved ranges remain
  panel-only with explanatory status; file-level findings open without coordinates.
  Failed/deleted/unrenderable targets explain failure without destructive fallback.
- `problems.test.mjs` executes actual viewer navigation code against the real files
  store with deferred reads/ticks: rapid targets, dirty/clean editor reuse, kept
  tabs, draft edits during render, failed reads, file-level/unverified locations,
  source/diff transitions and identity rejection. Pure handler tests execute scoped
  arrow navigation/wrap; SSR tests cover grouped escaped attributed findings.
  Source text-walker fixtures cover multiline UTF-16 endpoints; the existing real
  CodeMirror-state harness verifies exact selection and retained document/undo.
- Validation: frontend `npm test` **399/399 passed**, `npm run check` **0 errors**
  (existing ignoreDeprecations warning), `npm run build` passed (chunk warning).
  These are Node/SSR/controller fixtures, **not native browser focus/paint QA**.
  Native Tab/Enter/Space, disappearing-row focus, selection visibility, scrolling,
