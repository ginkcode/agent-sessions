# CD-19 — Safe LSP session lifecycle

- Status: ✅ Complete (2026-10-22)
- Stage: 2
- Estimate: 4 h
- Dependencies: CD-18
- Plan: [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Own initialization, synchronization negotiation, safe server-request handling,
shutdown/restart, and idle reuse around the CD-18 transport. Keep services managed
on the project host. APIs and proposed defaults remain provisional until CD-01.

## Current architecture and likely files

- Proposed `internal/codediagnostics/` session/lifecycle/request-policy files and tests.
- CD-07 manager and CD-03 process ownership/cleanup abstractions.
- `internal/engine/engine.go` and `internal/app/` shutdown wiring where necessary.
- Reuse existing backend ownership patterns, not the session-parser Diagnostics API.

## Implementation steps

1. Define a session state machine covering starting, initialized, idle, failed,
   disconnected, stopping, and stopped, with attachment/generation guards.
2. Require known-directory authorization and valid CD-02 approval/fingerprint before
   resolving and executing an installed server with fixed executable/argv.
3. Key reuse by authorized canonical root plus server configuration on its host.
   Enforce the proposed maximum of two active projects per backend.
4. Send initialize, validate capabilities, then initialized in protocol order.
   Negotiate UTF-16 or explicitly support conversion for the chosen encoding.
5. Record full/incremental sync and didSave capabilities for document operations.
   Advertise only client capabilities actually implemented.
6. Install explicit handlers for every required server request: bounded allowlisted
   workspace/configuration replies and safe error/negative replies for unsupported work.
7. Deny workspace/applyEdit and server-initiated commands; do not expand workspace
   folders outside approval. Do not provide arbitrary file-content request handlers.
8. Make file-watch registration support truthful: accept only bounded supported
   registrations or reject and expose stale unopened-file coverage (CD-25).
9. Retain hidden-dialog sessions for the proposed two-minute grace; cancel idle
   timers on reuse and evict idle projects under the active-project limit.
10. Implement shutdown request then exit, with deadlines and process-tree termination
    fallback. Disconnect, revoke, host switch, and app shutdown bypass idle grace.
11. Invalidate generations before restart/stop; cap restart attempts and expose Retry.
    Never let a crash loop or stale transport repopulate current results.

## Contract and security considerations

- Local/SSH/WSL execution stays on the project host; no frontend LSP tunnel.
- Trust is not sandboxing: servers/plugins can access dependencies or the network.
- Configuration/executable identity changes require renewed approval before auto-start.
- Bound initialization options, replies, request deadlines, queues, and stderr output.
- No document bodies or raw protocol traffic in logs, persistence, or telemetry.
- Push diagnostics are the baseline; pull-only servers remain unsupported.
- Initialization success does not establish workspace-wide coverage or version
  freshness. Unversioned publications cannot be certified against the current draft.
- Idle shutdown clears server-owned sets without deleting files-store drafts.

## Focused tests and manual QA

- Fake initialization: supported sync modes/encodings, missing capabilities,
  invalid replies, timeout, early exit, and concurrent attach reuse.
- Assert applyEdit/command/out-of-root workspace requests receive safe responses
  and cannot mutate files or stall the session.
- Fake clocks cover grace reuse, expiration, active-project eviction, and retry caps.
- Verify revoke/disconnect/shutdown kill descendants and suppress late publications.
- Verify rejected watchers expose fallback coverage rather than continuous-sync claims.

## Evidence (2026-10-22)

- Implemented `internal/codediagnostics/lsp_session.go` (`SessionManager`, one `lspSession` per
  generation) over the CD-18 transport; tests in `lsp_session_test.go` use an in-memory fake
  server, a fake process (`Terminate` = tree kill seam) and a fake clock (`After`). No real process,
  concrete adapter, document operation or Backend/App/RPC wiring was added.
- State machine: starting → initialized ⇄ idle → stopping → stopped/failed/disconnected. Terminal
  phases are per generation; Retry builds a new generation (random opaque ID) after invalidating
  the old one. `CurrentGeneration` is false for stopped/failed/revoked/replaced generations, and
  messages from invalid generations are drained and dropped.
- Gate: `AuthorizedRoot.Revalidate` (known directory), `validateCommand` (absolute fixed
  executable/argv/env bound to `Policy()`), `Trust.Preflight` and `Lease.Validate` right before
  spawn. Changed executable/config/argv or revoked approval never launches (tested: zero launches).
- Reuse key: canonical host-scoped root + provider + exact config policy. Concurrent attaches share
  one start. Max 2 active projects; only the oldest idle project is evicted, visible ones never;
  otherwise `limitExceeded`.
- initialize sends only `general.positionEncodings: ["utf-16"]` and `rootUri` (no workspace
  folders, no dynamic registration, no watchers, no edits). `initialized` follows a validated
  reply. Accepted: UTF-16 (or unset) encoding, open/close sync with full or incremental change;
  `save` recorded (didSave only, never text). Rejected with bounded errors: no/none sync, utf-8/32,
  missing capabilities, invalid shapes, server error, timeout (10 s), early exit. Pull-only
  advertisement is recorded and unsupported; push stays the baseline.
- Server requests all get a prompt reply: `workspace/configuration` is validated (≤16 items, bounded
  sections, scopes inside the root) and answered with nulls, otherwise -32602;
  `applyEdit`, `executeCommand`, `workspaceFolders`, `showDocument`, unknown methods → -32601.
- File watching: `client/registerCapability` (including `didChangeWatchedFiles`) is rejected with
  -32601 and counted; coverage is always `externalChanges: "unwatched"` with a notice, never
  `watching`. CD-25 owns reconciliation.
- Idle: 2 min grace via injected timer; reuse cancels the idle period (a stale timer cannot stop a
  reused session). Expiry runs shutdown/exit under a 5 s deadline, then always terminates the tree.
  Revoke, host disconnect and Close bypass grace; revoke/disconnect kill immediately, Close tries
  graceful shutdown with the kill fallback after the deadline. Process cleanup is bounded.
- Restart: crashes/failures leave the session `failed` (plain Attach does not relaunch);
  `Retry` is capped at 3 (configurable lower), reported via `RetryAvailable`, then
  `ErrSessionRestart`.
- Logging/privacy: errors are mapped to bounded plain-text CD-01 codes; server error text, stderr and
  launch errors never reach results. Nothing retains document text or frames.
- Not claimed: native process-tree behavior (the real `startProcess` is reused by a future adapter
  launcher; only the `Terminate` seam is faked here), draft freshness, workspace coverage.
- Dependency note: Stage 1 HOLD/CD-17 native QA and the CD-09 remote identity block are recorded
  exceptions; they do not block this local lifecycle, and it resolves neither. No capability is
  enabled for users.
- `go vet ./...`, `go test -race ./...` and `go tool golangci-lint run ./internal/codediagnostics/...`
  pass (0 issues).
