# PS-03 — Search pane

- Status: ✅ Done (2026-10-24)
- Estimate: 4 h
- Dependencies: PS-02
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

A Search mode in the Go to File left pane that feels like VS Code's search
view: type, see grouped matches as you type, click to jump.

## Design

- The left pane gets a small mode switch: **Files** and **Search** (and
  **Changes** after GIT-04). Cmd/Ctrl+Shift+F opens Go to File in Search mode
  and focuses the field, with the current selection as the initial text.
- Field toggles: match case (Aa), whole word (ab), regex (.*). A disclosure
  shows *files to include* and *files to exclude*.
- Searches start 250 ms after typing stops; a new search cancels the previous
  one. The summary reads "N results in M files", plus "(limited to N)" when
  truncated, or the regex error in place.
- Results are grouped by file (icon, name, directory, count), each group
  collapsible, each match a line with the match highlighted. Click opens the
  file and selects the match range, reusing the Problems navigation path.
- Drafts: files with an unsaved draft are searched in memory with the same
  options, and those results replace the disk results for that file.
- Keyboard: Enter in the field goes to the first result, Up/Down move through
  results, F4/Shift+F4 go to the next/previous match anywhere in Go to File
  (as in VS Code, the editor included), folded files too.
- A click opens the match in the preview tab, as a click in the file list
  does; a double click or Enter keeps it in a tab.
- The search text and options are kept per project while the app runs.
- Hidden when the host lacks `searchFiles`, with a note.

## Done when

- Server-render tests cover the mode switch, toggles, grouped results, the
  truncation and error summaries, and the unsupported note.
- Store tests cover debounce, cancel of stale searches, draft overlay and
  result navigation order.
- Manual check still needed: focus, scrolling and highlight paint in the app.
