# AG-06 — Alerts

- Status: ✅ Done (2026-10-24)
- Estimate: 4 h
- Dependencies: AG-05
- Plan: [editor-essentials.md](../plan/editor-essentials.md)

## Goal

The user notices quickly when an agent needs them or has finished, without
watching the terminal.

## Design

- **Tabs:** a coloured dot per state (working: pulsing accent, needs you:
  amber, done: green). The panel toggle in the status bar shows the most
  urgent state when the panel is closed.
- **Session list:** linked sessions show the same dot next to the title.
- **Window title:** "(N) Agent Sessions" while N tabs need the user.
- **System notifications**, only while the window is not focused, at most
  one per tab per state change: "Claude Code needs you: <session title>" or
  "Codex finished: <title>". Clicking it focuses the app and the tab where
  the platform allows. Go package `internal/notify`:
  - macOS: `osascript` `display notification`;
  - Linux: the `org.freedesktop.Notifications` D-Bus interface through
    `gdbus`, falling back to `notify-send`;
  - Windows: a WinRT toast through PowerShell.
  A missing helper turns notifications off silently with one note in
  Settings.
- **Settings:** "Notify when an agent needs me" and "Notify when an agent
  finishes", both on by default.

## Done when

- Store tests cover title counts, notification de-duplication and the focus
  rule. Go tests cover the per-platform argv builders.
- Manual check still needed: notifications on each platform.

## Outcome

- **Notifications use the Wails runtime, not `internal/notify` helpers.**
  Change from the plan: Wails 2.14 ships native notifications (the
  notification center on macOS, D-Bus on Linux, toasts on Windows). This
  beats `osascript`, `notify-send` and PowerShell on the points that matter:
  - the notification carries the app's own name and icon;
  - clicking it reaches the app, which raises its window and shows the tab
    (`osascript` notifications open Script Editor; `notify-send` has no
    click back);
  - no helper program has to be installed or found.
  So the Go tests cover the alert logic through a fake notifier instead of
  argv builders.
- `internal/app/notify.go`:
  - `NotificationStatus`, `PrepareNotifications`, `Notify` and
    `ClearNotification`, bound to the frontend;
  - notifications start on first use; permission is asked at most once per
    run, and only by `PrepareNotifications`;
  - when unavailable, the status says why and what to do: macOS 11 or later,
    no notification service on the desktop, could not start (the error), or
    turned off ("Allow them in System Settings → Notifications → Agent
    Sessions" on macOS);
  - each tab has one notification, replaced by the next. Identifiers carry
    the process id, so a window ignores clicks on another window's
    notifications;
  - a click raises the window and emits `notify:open` with the tab;
  - notifications are cleaned up at shutdown.
- Frontend:
  - `src/lib/alerts.ts`: urgency order (needs, done, working), labels,
    notification text ("Claude Code needs you", body: the tab's session
    title and what the agent's own notification said) and `AlertLog`.
    `AlertLog` allows one alert of each kind per prompt: a tab that needs
    the user, works briefly and needs them again before they type alerts
    once. The prompt count is the tracker's count of user inputs.
  - `stores/alerts.svelte.ts`:
    - follows `terminals.onAttention`;
    - sets the window title count, e.g. "(2) Local — Agent Sessions";
    - notifies only while the window is in the background;
    - readies notifications, and asks for permission where needed, when the
      first agent tab starts working;
    - removes a tab's notification when the user looks at the tab or it
      ends;
    - a click shows the tab;
    - the two settings are kept in `localStorage`, both on by default.
  - `AttentionDot.svelte` is used in three places:
    - agent tabs: a running agent tab's dot is its state, grey while
      nothing is known; the tooltip names the state;
    - the status-bar terminal toggle, while the panel is hidden: the most
      urgent state, also in its tooltip;
    - session-list rows of sessions running in a tab: in place of the live
      dot.
    A new theme colour `--status-needs` (amber) marks needing the user.
    Working pulses, except with reduced motion.
  - Settings → Terminal → Agent alerts has the two options and a note on
    what shows where. When notifications can't show, it gives the reason
    and the next step. Opening the section rechecks permission.
- Tests:
  - `test/alerts.test.mjs`: urgency, text, title counts, de-duplication,
    the focus rule, notifications turned off, unavailable notifications,
    clicks showing the tab, saved settings.
  - `test/settings.test.mjs`: the alert options and the reason.
  - `internal/app/notify_test.go`: permission asked once, sending and
    replacing, denied, unavailable, start failure, outside the desktop app,
    clicks (including another window's).
- Manual checks still needed, per platform:
  - **macOS:** the packaged app (notifications need its bundle
    identifier; where they can't start, Settings shows the error). Check
    the permission prompt and the click.
  - **Linux:** a D-Bus notification server; the click (servers differ).
  - **Windows:** the toast and its click. Wails registers the app for
    toasts under the current user's registry (HKCU).
