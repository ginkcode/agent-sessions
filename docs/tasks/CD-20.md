## Goal

Route versioned document open/change/save/close across Backend, App, and RPC to
host-local language sessions, preserving authorization and bounded transport.
Operation names and schemas are provisional until the CD-01 contract is finalized.

## Current architecture and likely files

- `internal/engine/{backend,service,engine}.go` for context-first routing.
- `internal/app/` bindings, offline behavior, service adapters, and tests.
- `internal/rpc/{types,client,server}.go` and scoped operation/notification tests.
- Proposed `internal/codediagnostics/` document/session management and tests.
- `frontend/src/lib/{api,types}.ts`; regenerate bindings by established workflow.
- Existing Backend.Diagnostics returns provider parsing diagnostics; leave it separate.

## Implementation steps

1. Map CD-01 operations to CD-19 sync capabilities without introducing a second
   owner of user text. Save coordinates change plus didSave, not a source write.
2. Define identity checks for backend connection, authorized root, attachment token,
   generation, document URI/path, monotonic version, and saved revision when relevant.
3. Add context-first Backend/Service methods and App forwarding with offline errors.
   Apply known-directory and execution approval checks on the project host.
4. Implement open with actual displayed text, then ordered versioned changes.
   Reject duplicate-invalid opens, nonmonotonic versions, and changes after close.
5. Respect negotiated full/incremental sync and save options; validate change ranges
   against the known document snapshot and negotiated position encoding.
6. Close documents deterministically and clear their owned live sets per CD-01.
   Explicit reopen starts a fresh valid lifecycle, not an old publication channel.
7. Extend CD-09's separate live-diagnostics capability; an absent flag on old servers
   disables live controls/calls while preserving browsing/editing and project checks.
8. Add bounded RPC parameters, decoded text/change counts, and result/event batches.
   Account for JSON escaping/envelope bytes below the existing app RPC frame limit.
9. Return explicit unsupported/oversize/disconnected outcomes and invalidate failed
   synchronization; never pretend a dropped change reached the server.
10. Reconcile event sequence gaps through snapshots and generation checks, not blind
    replay of draft-bearing requests after reconnect.

## Contract and security considerations

- Canonicalize/validate paths and file URIs, including Windows paths and symlinks.
  Reject traversal, arbitrary schemes, and out-of-root document-content access.
- Processes run where files live (local/SSH/WSL), only with current trust approval.
- Safe server requests remain allowlisted in CD-19; operations cannot authorize
  applyEdit, server commands, or arbitrary workspace expansion.
- Do not log/persist draft bodies, raw frames, or sensitive diagnostic messages.
- Push publications replace a document set, including empty publications.
- Accept versioned results only for the matching snapshot; unversioned results
  remain uncertain and their ranges must be invalidated after edits.
- Opened-document analysis is not full-workspace or continuous external-file coverage.

## Focused tests

- Round-trip open/change/save/close across local and fake RPC backends.
- Capability absence, offline calls, unknown directory, revoked trust, invalid token,
  wrong host/root, old generation/version, duplicate close, and disconnect races.
- Oversized escaped text, many small changes, bounded notifications, and size errors.
- UTF-16/non-BMP/CRLF change locations and negotiated full/incremental sync.
- Late and empty publications cannot replace another document's current results.

## Acceptance checklist

- [x] Local and RPC routes enforce identical identity, trust, and version semantics.
- [x] Save coordination does not write files or become a second draft owner.
- [x] Old remote servers browse/edit without invoking unsupported live operations.
- [x] Transport limits and freshness failures are explicit and covered by tests.

## Out of scope

Frontend lifecycle hooks (CD-21), concrete adapters, automatic saving, pull diagnostics,
custom commands, source edits, and increasing RPC frame limits to avoid proper bounds.

## Evidence and caveats

- Implemented in `internal/codediagnostics` (documents.go, lsp_documents.go), Engine, App and RPC (`code_diagnostics_live.go`); verified with a fake LSP server only. `go test ./...`, `-race` on touched packages and scoped lint pass.
- `liveCodeDiagnostics` is never advertised in production (no concrete LSP adapters or session resolver), so live calls return `unsupported` before any process starts. Old remote servers are unaffected.
- `PublishDocumentResults` is not yet wired to publishDiagnostics notifications.
- Wails bindings (gitignored) were not regenerated and the frontend is untouched; CD-21 owns the lifecycle bridge.
