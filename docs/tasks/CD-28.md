## Implementation steps

1. Confirm Stage 1 CD-17 and live CD-27 gates, including unsupported environments
   and adapter limitations, before enabling automatic behavior in a release.
2. Define separate explicit on-open/on-save preferences with an off default and
   clear host/root scope. Execution approval alone must not imply automatic checking.
3. Explain saved-file-only coverage and reuse CD-02 trust decisions. Automatic work
   requires both current authorization/trust and the applicable user opt-in.
4. Schedule on-open work after immediate dialog rendering and asynchronous discovery;
   unsupported/missing providers remain independently unavailable.
5. Trigger on-save only after confirmed successful save/reconciliation of disk state.
   Failed, conflict, uncertain, canceled saves and ordinary typing do not trigger checks.
6. Coalesce rapid opens/saves and repeated manual requests into bounded queued work,
   respecting one checker process per project and two per backend.
7. Capture current project identity/generation and run ID; canceled/superseded runs
   cannot publish over newer runs, even when provider completion arrives out of order.
8. Reconcile external disk changes before reruns via CD-25; never save drafts to check.
   Mark results stale when their saved revision no longer matches applicable state.
9. Reuse atomic successful provider replacement, including empty sets. Failure/cancel
   retains prior results marked stale; bounds expose partial/truncated coverage.
10. Integrate Check/Cancel/Retry status with automatic scheduling. Define cancellation
    behavior so a canceled run is not immediately resurrected by queued duplicate triggers.
11. On opt-out/revoke/disconnect/host switch, cancel applicable queued work and timers;
    revoke/disconnect stops owned running processes and invalidates stale generations.

## Contract and security considerations

- Checks run on the project host (local/SSH/WSL), using approved installed executables
  and fixed argv; no npx downloads, package scripts, custom shell, or automatic install.
- Persisted opt-in is not a persisted approval. Revalidate CD-02 fingerprint changes
  before automatic execution and expire session grants on disconnect/app exit.
- Approval explains plugins/config/dependencies and cache/network behavior; not sandboxing.
- Reuse proposed 120 s timeout, 10 MiB output, 10,000 findings and bounded stderr/messages
  as finalized by prior tasks; result batches must fit app RPC framing.
- Live servers continue push-only behavior and safe request denial of edits/commands/
  root expansion. Automation does not add pull support or certify unversioned drafts.
- Saved-file ranges must not decorate dirty drafts; unopened/live/watch coverage remains
  separate and never becomes an all-clean claim after an automatic checker run.
- No source bodies/raw traffic/result persistence or automatic telemetry.

## Focused tests and manual QA

- Fake clocks/processes prove off-by-default behavior, independent trigger settings,
  no execution without trust, immediate dialog open, and no per-keystroke full check.
- Burst saves/opens/manual checks coalesce and respect project/backend concurrency caps.
- Test confirmed versus uncertain saves, opt-out/cancel/revoke races, host changes,
  external edits, output caps, superseded results, failure retention, and empty clears.
- Manual approved local/remote smoke: opt in, open/save, cancel/retry, opt out, and
  verify status/coverage labels and intact dirty drafts throughout.
