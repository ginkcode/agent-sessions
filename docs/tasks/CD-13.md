## Goal

Show consistent error/warning counts on files and ancestor folders, with shared
exact deduplication and independent Git status indicators.

## Grounding in current code

- `FilePicker.svelte` derives tree rows with `buildFileTree` and Git folders with `folderStatus`.
- It separately renders recursive folders, file rows, and search matches.
- Git letters/dots, ignored tags, deleted paths, and search selection already occupy row space.
- Ignored files are searchable but absent from the normal tree; listings can be truncated.
- `frontend/test/files.test.mjs` tests pure helpers; `go-to-file.test.mjs` fixture-renders rows.

## Concrete steps

1. Use CD-10's canonical visible findings and selectors; establish one shared
   aggregation path for summary, Problems panel, tree, and inline consumers.
2. Implement or finish pure exact-equivalence helpers at the agreed store boundary.
   Deduplicate by path, optional range, severity, message, and optional code only.
3. Preserve provider/source attribution on equivalent findings; retain provider-owned
   originals so removing one provider does not erase another provider's finding.
4. Treat file-level findings as countable entries; keep distinct locations and
   similar-but-not-identical messages separate. Default counts include errors/warnings only.
5. Compute per-file counts once, then add each file's counts to each ancestor once.
   Do not recursively add both leaf counts and already aggregated child totals.
6. Use component-aware path ancestry; `src/a` must not include `src/ab/file.ts`.
   Normalize according to CD-01 rather than lowercasing host-sensitive paths locally.
7. Add readable error/warning badges to folder buttons, file buttons, and search rows.
   Reuse one compact presentation for counts and accessible severity labels.
8. Keep Git status visible and independent; handle narrow rows without pushing
   Git letters, ignored tags, selected styling, or diagnostic counts out of view.
9. Do not make badge state depend on expanded folders, search filters, or open tabs.
   Findings outside the current listing remain available in summary/Problems panel.
10. Preserve freshness/partial context through accessible labels or nearby status;
    stale retained counts must not imply a fresh successful check.
11. Recompute on provider replacement/empty results, clear/delete, revocation,
    and generation changes, using store invalidation rather than file-tree mutations.

## Contract and security considerations

- CD-01 finalizes identities and equivalence; proposed API/helper names are provisional.
- Keep code diagnostics separate from existing `provider.Diagnostics` / `Backend.Diagnostics()`.
- Aggregate only validated authorized project-relative paths; out-of-root findings are status, not rows.
- Do not infer platform case-folding from the frontend host when analyzing remote paths.
- Never parse messages as HTML or derive actionable links from badge titles.
- Findings stay in memory; this task adds no result persistence or telemetry.

## Focused tests and manual checks

- Exact duplicates across two providers count once while retaining both sources.
- Different code, severity, message, range, or absent range remains a separate finding.
- Provider replacement/removal preserves surviving attribution and clears successful empty sets.
- Nested/sibling folders, root files, empty folders, and prefix collisions produce correct totals.
- Information/hint findings do not inflate default error/warning totals.
- Collapsed folders, search-only ignored files, truncated listings, and unopened files stay consistent.
- Fixture-render Git status plus diagnostics plus ignored tags and assert accessible labels.
- Manually check narrow widths, large counts, light/dark themes, and stale-state clarity.
- Run frontend `npm test` and `npm run check`.
