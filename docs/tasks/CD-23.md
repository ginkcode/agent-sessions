## Implementation steps

1. Spike installed LSP wrapper/server and TypeScript versions; do not assume raw
   tsserver speaks LSP Content-Length JSON-RPC or shares a supported adapter API.
2. Record executable/argv, required runtime/dependencies, version bounds, push support,
   sync mode/encoding, and observed nonzero-exit/failure behavior in fixtures/notes.
3. Re-estimate before committing support; split if wrapper/version compatibility
   requires more than the allocated four hours.
4. Discover package.json/tsconfig/jsconfig and nested packages inside the authorized
   root. Define monorepo selection limits without parent-root promotion.
5. Resolve host-installed or approved project-local binaries without npx, package
   scripts, shell interpolation, dependency installation, or fallback downloads.
6. Report missing wrapper/runtime/TypeScript and unsupported versions as independently
   unavailable; never block browsing or unrelated Go/Svelte checker providers.
7. Configure an owned session and route opened JS/TS read-only/draft documents through
   CD-21. Establish extension/ownership rules that CD-24 can refine for Svelte.
8. Normalize push findings and empty clears into CD-01 provider-owned document sets.
   Validate URIs/ranges and preserve optional codes, attribution, and coverage.
9. Measure versioned/unversioned publication behavior for each supported combination.
   Reject mismatched versions; invalidate unversioned ranges on edits and label
   uncertain results until a tested server-specific strategy exists.
10. Expose limited project coverage and external-change/watch behavior explicitly;
    absence of a push is not evidence that an unopened file is clean.

## Contract and security considerations

- Execution stays on the file host for local/SSH/WSL, gated by known-directory
  authorization and CD-02 trust, including executable/config fingerprint changes.
- Project-local binaries/plugins are executable project content, not safer tools.
- Repositories may read referenced dependencies or use networks/caches; do not promise
  sandboxing or app-enforced no-write/no-network execution.
- Use bounded CD-18 transport, bounded discovery, and CD-19 safe server requests.
  Deny applyEdit, server commands, arbitrary configuration, and root expansion.
- Reject out-of-root diagnostic links; do not fetch referenced source for the server.
- Drafts/raw protocol/diagnostic messages remain in memory, without automatic telemetry.
- Push is the baseline; pull-only combinations are unsupported until a later adapter.

## Focused tests and manual QA

- Fixtures cover supported/unsupported versions, missing binaries/dependencies,
  package selection, malformed output, errors/warnings, empty clears, and crashes.
- Verify Unicode/CRLF coordinates, stale versions, unversioned uncertain results,
  oversized messages, and malicious file URIs/configuration requests.
- Test monorepo/nested roots and escaped out-of-root references without extra file access.
- In an approved installed-server project, edit/fix an unsaved TS error and verify
  panel/marker coherence while retaining editor undo and checker saved-file labels.
