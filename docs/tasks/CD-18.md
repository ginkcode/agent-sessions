# CD-18 — Bounded LSP stdio transport

- Status: Not started
- Stage: 2
- Estimate: 4 h
- Dependencies: CD-07
- Plan: [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Implement a bounded, independently testable LSP stdio JSON-RPC transport using a
fake server, without coupling protocol parsing to the UI or a particular server.
All API names, payloads, and limits remain provisional until CD-01 finalizes them.

## Current architecture and likely files

- Add transport and focused tests under proposed `internal/codediagnostics/`.
- Add a fake-server helper/test fixture under that package's test data or tests.
- Inspect `internal/rpc/framing.go` for resource-bound conventions only.
- Existing app RPC uses newline-delimited JSON, not LSP Content-Length framing.
- Integrate with the CD-07 manager rather than `provider.Diagnostics`.

## Implementation steps

1. Confirm CD-01 identity/error conventions and CD-07 ownership boundaries.
2. Define reader/writer interfaces so pipes and fake streams work in unit tests.
3. Parse Content-Length headers and exact UTF-8 byte bodies incrementally.
   Handle fragmented reads, multiple frames, EOF, and malformed headers explicitly.
4. Bound header length/count, body bytes, pending requests, and queued messages.
   Reject invalid/overflowing lengths before allocating the advertised body.
5. Serialize writes, handle short writes, and avoid interleaved frame bytes.
6. Correlate responses with request IDs; classify notifications and server requests.
   Do not let a slow handler block cancellation or fill an unbounded queue.
7. Add request deadlines and context cancellation with `$/cancelRequest` where
   applicable; remove canceled waiters and ignore their late responses safely.
8. On EOF/protocol failure, fail pending requests once and release blocked work.
9. Keep stderr separate from stdout framing; capture only bounded sanitized errors.
10. Expose bounded protocol errors/status to the manager; do not silently drop
    diagnostics or claim successful delivery after overflow.

## Contract and security considerations

- Transport is host-local stdio: local, SSH, and WSL processes run by project files.
- This task does not authorize execution; the manager must require known-directory
  authorization and CD-02 trust before starting any process or discovery that runs tools.
- Carry attachment/generation identity through the owner, invalidating dead streams.
- Server-request dispatch must be explicit; transport must never execute commands,
  apply edits, fetch arbitrary files, or authorize workspace expansion.
- CD-19 supplies deny/allowlist responses; unknown requests must not hang forever.
- Do not log/persist raw frames, document bodies, or diagnostic source excerpts.
- LSP frame limits are separate from app RPC's current 64 MiB limit; account for
  envelopes and bounded batching before results cross app RPC.
- Baseline is push diagnostics, not pull. Framing cannot establish draft freshness;
  version checks and uncertain unversioned publications belong to higher layers.

## Focused tests

- Split headers/bodies at every meaningful boundary; parse consecutive frames.
- UTF-8 multibyte bodies use byte lengths, not rune/UTF-16 counts.
- Reject absent/duplicate-invalid lengths, oversized headers, huge lengths, bad JSON,
  truncated bodies, and framing garbage without panic or unbounded allocation.
- Exercise concurrent requests, reversed replies, unknown IDs, timeout/cancel races,
  blocked writers, EOF, slow consumers, and pending-request limit exhaustion.
- Verify server requests are delivered without being mistaken for responses.
- Verify shutdown leaves no stuck reader, writer, pending waiter, or fake process.

## Acceptance checklist

- [ ] Fake-server tests establish correct bounded LSP framing and request correlation.
- [ ] Cancellation, failure, and overflow have deterministic visible outcomes.
- [ ] No app RPC framing reuse, raw traffic logging, or server-triggered execution.
- [ ] Manager integration preserves attachment/generation invalidation boundaries.

## Out of scope

Initialization, concrete adapters, UI, pull diagnostics, remote WebSockets, and tool
installation. If bounds or concurrency design exceed four hours, split before coding.
