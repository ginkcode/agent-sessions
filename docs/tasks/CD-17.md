# CD-17 — Cross-host/platform QA and Stage 1 release gate

- Status: Partial / blocked — non-GUI preflight and QA matrix recorded; no native checks performed; Stage 1 HOLD ([record](../plan/code-diagnostics-qa.md))
- Stage: 1
- Estimate: 4 h
- Dependencies: CD-16
- Plan: [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Manually validate explicit project checks on local/SSH/WSL hosts across
Windows/macOS/Linux, document limitations, and record a Stage 1 release decision.

## Grounding in current code

- Go to File uses `files.dir` for the selected root and `link.dataHost` for the data host.
- Dialog/viewer remain mounted when hidden, preserving tab state and preview preferences.
- Dirty drafts, uncertain saves, and close/host-switch prompts have existing coordinators.
- FilePicker combines tree/search/Git state; SourceView has wrapped/unwrapped gutters.
- FileEditor loads lazily and caches editor state, so repeat-open/tab-switch QA matters.
- Node/SSR tests do not validate native focus, WebView layout, remote tools, or process trees.

## Concrete steps

1. Record the tested commit/build, app mode, client OS, project host OS/transport,
   checker executable/version, approved root, and CD-04 supported-version decision.
2. Use disposable contained Go and Svelte projects with known findings and clean variants.
   Include nested supported roots, missing dependencies, Unicode/CRLF paths/text,
   and one intentionally unsupported configuration; do not use personal secret content.
3. Execute the host/platform matrix below using preinstalled tools only.
   Distinguish client OS from checker host OS and mark unavailable cells untested.
4. Exercise approval, explicit checks, cancellation, retry, revocation, disconnect,
   and reopen against both adapters independently and together where supported.
5. Confirm dialog/search becomes usable before discovery completes and no check runs
   on open/save. Measure cold/warm opening on the same fixture and record observations.
6. Validate findings on unopened files, range navigation, source/editor markers,
   Git coexistence, empty replacements, partial coverage, and saved-file labels.
7. Retain dirty and uncertain drafts while checking/navigating/switching hosts;
   verify text, undo, tab guards, and disk bytes remain unchanged by checking.
8. Inspect owned checker processes after cancel/revoke/disconnect/app shutdown;
   include a checker fixture with descendants where platform tooling permits.
9. Check bounded/truncated output, sanitized failure text, missing tools, and an
   older remote lacking capability flags without degrading browsing/editing.
10. Record pass/fail/blocked evidence and known limitations in a focused QA record.
    Link failing cells to blockers; do not label an untested platform as passed.
11. Review Stage 1 acceptance criteria with CD-16 results; recommend release/hold
    with an explicit owner decision for any reduced platform coverage.
12. Keep this within four hours by prioritizing existing environments; split/re-estimate
    remaining matrix work rather than silently claiming exhaustive coverage.

## Explicit manual QA matrix

| Host/client coverage | Run | Evidence required |
|---|---|---|
| Local macOS client and host | Go/Svelte installed and missing-tool cases | Versions, findings, empty rerun, UI focus |
| Local Linux client and host | Same fixtures in supported WebView | Wrap/gutter alignment, cancellation, cleanup |
| Local Windows client and host | CRLF/non-BMP text and Windows roots | Correct ranges, argv paths, process-tree cleanup |
| SSH project host | At least one real remote supported OS | Tools execute remotely; reconnect invalidates old runs |
| Windows client with WSL host | Supported distro and contained roots | Linux-side tool resolution, approval identity, cleanup |
| Older SSH/WSL server | Capabilities omitted | No diagnostics controls; browse/edit still work |

Apply the following checks across available matrix cells and record any reduced pairing:

| Scenario | Expected result |
|---|---|
| Fresh/unapproved root, Not now, session/always grants | No execution before approval; correct persistence scope |
| Revoke or executable/config fingerprint change | Owned work stops; renewed approval before execution |
| Findings, fix, empty rerun, failure, cancel/retry | Counts agree; only success replaces; old failures stay stale |
| One checker unavailable, nested/unsupported package, cap | Explicit provider/partial coverage; no “all clean” claim |
| Dirty draft and diagnostic navigation from preview | No save/loss; source navigation; no stale draft overlays |
| Keyboard, narrow width, themes, presentation, repeated reopen | Accessible controls/messages; no broken focus or caches |
| Host switch/disconnect/shutdown during run | No cross-host results or owned-process leaks |

## Contract and security considerations

- APIs remain provisional until CD-01; test the finalized negotiated contract, not guessed calls.
- Code diagnostics are separate from `provider.Diagnostics` / `Backend.Diagnostics()`.
- Explain executable configuration/plugins and non-sandbox behavior; never install tools for QA implicitly.
- Confirm canonical host/root trust, denied out-of-root navigation, and escaped hostile messages.
- Keep QA evidence sanitized: no draft bodies, raw protocol traces, secrets, or persisted findings dumps.
