> **Update 2026-10-23:** Remote diagnostics are implemented with a host-side identity (machine ID, UID, installation ID; kind from the launcher's `AGENT_SESSIONS_DIAGNOSTICS_HOST`) instead of a client-verified host key. Covered by unit and RPC tests only; no real SSH or WSL run, so this task stays open. See the [editor (Zed) model](../plan/code-diagnostics-zed-model.md).

## Goal

Expose Stage 1 code diagnostics over existing host RPC, with negotiated support,
scoped bounded notifications, disconnect cleanup, and old-server compatibility.
Implement finalized [CD-01](CD-01.md) contracts, not a frontend LSP tunnel.

## Current code grounding

- `internal/rpc/types.go` uses protocol version 1 with optional capabilities;
  older servers leave newer flags false rather than breaking the handshake.
- `framing.go` uses newline-delimited JSON and a 64 MiB cap. This is application
  RPC, distinct from later LSP Content-Length framing.
- `Server.Serve` tracks handler cancellation and waits on exit; `Notify` writes
  arbitrary notifications, so ownership and backpressure need explicit handling.
- `blame_test.go` demonstrates capability absence and no-write unsupported calls.

## Concrete implementation steps

1. Add separate project-check and live-diagnostics capability flags using CD-01
   finalized names. Advertise only project checks in this stage; absent flags
   decode false. Inspect both starter-provided and default handshake capabilities.
2. Add finalized request/result/error types and dispatcher cases for Stage 1
   attach/detach, snapshot, approval/revocation, run/cancel, and retry semantics.
   Implement matching Client Backend methods, replacing CD-08 conformance stubs.
3. Gate unsupported calls before transport writes where existing client patterns
   allow it. Preserve method-not-found/unsupported behavior if peers disagree;
   do not require a protocol bump without a documented compatibility reason.
4. Bind attachment/session tokens to the owning connection and authorized root.
   Route through Engine's checks; reject foreign tokens, stale generations,
   arbitrary directory requests, and approval reuse from another host/connection.
5. Forward only scoped code-diagnostics notifications to the owning client, then
   through App's current-generation event path. Avoid broadcasting diagnostic
   messages to unrelated windows, attachments, or connections.
6. Serialize events/snapshots in CD-01 bounded batches, accounting for escaped
   messages and envelope overhead. Support atomic snapshot assembly, sequence-gap
   resnapshot, explicit overflow/partial status, and bounded pending writes.
7. Separate canceling a single RPC wait from canceling owned checker work according
   to CD-01. On EOF, heartbeat timeout, context cancellation, or close, detach
   ownership, expire session grants, cancel checks, and invalidate publications.
8. Keep all file/tool work on the project host for Local/SSH/WSL. Do not copy
   project files locally or add remote WebSockets or LSP transport semantics.
9. Update connection capability exposure/notification forwarding in App and server
   startup wiring where necessary, retaining old browse/edit behavior unchanged.

## Contract and security considerations

- Follow CD-01 and preserve existing `Diagnostics` RPC/provider health semantics.
- Remote client identity is not a directory grant; trust remains host/root scoped.
- Never log document bodies, raw protocol traffic, or diagnostic message payloads.
- No silent notification drop followed by success; slow peers must receive a
  bounded recoverable state or a clean disconnect with stale frontend state.

## Focused tests

- Pipe-pair round trips, capability decoding without new fields, unsupported calls
  writing zero bytes, and browsing/editing against an older-server fixture.
- Scoped notifications, cross-token denial, revoke/cancel, sequence/snapshot races,
  escaped-message byte limits, overflow recovery, and independent provider states.
- Disconnect during a run, heartbeat timeout, late notification after reconnect,
  handler cleanup, and no process/session-grant leaks; use fake checker ownership.
