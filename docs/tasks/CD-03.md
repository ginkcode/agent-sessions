# CD-03 — Bounded checker process supervisor

- **Status:** Complete
- **Stage:** 1 — Project checks
- **Estimate:** 4 h
- **Dependencies:** CD-02
- **Plan:** [code-diagnostics.md](../plan/code-diagnostics.md)

## Goal

Build a host-local checker supervisor with deterministic lifecycle, limits, and
cancellation. Follow finalized [CD-01](CD-01.md) contracts and CD-02 trust policy;
keep execution mechanics independent of parsers and result-set ownership.

## Current code grounding

- Engine owns a run context, cancellation, and background wait group in
  `internal/engine/engine.go`; diagnostics work must ultimately join its shutdown.
- Existing `exec.CommandContext` use in `internal/remote/` starts transport tools,
  not an approved checker abstraction or guaranteed child-tree cleanup.
- `internal/rpc/framing.go` caps serialized frames at 64 MiB; raw capture limits
  alone do not bound serialized findings or frontend memory.

## Concrete implementation steps

1. Define the smallest supervisor/adaptor seam required by CD-01 and CD-02:
   executable identity, fixed argv, contained working directory, bounded streams,
   outcome, run identity, and cancellation. Do not finalize parser-specific flags.
2. Inject process creation, timers, and limits so tests need no installed checker.
   Revalidate approved root/executable/config fingerprint before launch.
3. Execute directly with argv, never a shell command string. Define environment
   inheritance/overrides and executable resolution on the project host; prevent
   implicit downloads/toolchain installation where controllable.
4. Enforce one checker process per project and two per backend. Coalesce repeated
   requests, bound pending work, and define supersession so old completions cannot
   publish over the latest run. Leave result replacement itself to CD-07.
5. Implement concurrent stdout/stderr draining with bounded capture, individual
   message limits, and cancellation-safe pipe handling. Avoid deadlock when one
   stream fills; preserve an explicit output-limit/partial outcome.
6. Validate proposed defaults: 120 s timeout and 10 MiB captured output; document
   exact accounting and configurable test overrides. Carry finding-budget signals
   for the manager's proposed 10,000-finding project cap.
7. Implement platform-specific child-tree termination and bounded wait/cleanup on
   cancel, timeout, revoke, disconnect, and shutdown; ordinary parent-only Kill
   must not be treated as proof descendants are gone.
8. Return typed outcomes distinguishing launch/tool failure, accepted diagnostic
   exit, cancellation, timeout, and limits. Adapter policy decides accepted exits;
   a nonzero exit must not automatically erase valid findings or imply failure.
9. Add shutdown/idempotency hooks that CD-07/CD-08 can own without holding engine
   locks while waiting for processes or emitting events.

## Likely files

- New supervisor, process abstraction, platform helpers, and tests under
  `internal/codediagnostics/` (filenames chosen during implementation).
- `internal/engine/engine.go` only if needed for the lifecycle seam; full routing
  and application shutdown integration remain CD-08.
- Test helper subprocess executable or Go test-helper mode for real pipe behavior.

## Contract and security considerations

- All operations and outcomes follow finalized CD-01; no scanner-health reuse.
- No `npx`, package scripts, source fixes, installation, or shell interpolation.
- Sanitize/bound user-visible stderr; do not log raw output or source excerpts.
- Approved project-local binaries are executable project content, not safe tools
  merely because they are inside the root. Checks may still write build caches.

## Focused tests

- Fake runner/clock: concurrency, coalescing, queue limits, cancel before start,
  timeout, supersession, revocation, and repeated shutdown.
- Helper subprocess: interleaved streams, oversized output, blocked pipes,
  descendant cleanup, launch failure, and no orphan waits/goroutines.
- Assert exact argv/cwd, no shell path, and no process after failed grant checks.

## Completion

Implemented the internal argv-only supervisor, explicit fingerprint-bound command
policy/environment, bounded two-worker/project-slot scheduling, coalescing and
supersession, trust revalidation, bounded concurrent capture, typed outcomes and
idempotent joined shutdown. Unix process groups and suspended Windows Job Object
assignment own ordinary descendants. No production adapter is executed/enabled.
See [execution semantics and limitations](../plan/code-diagnostics-supervisor.md).

Validation: focused fake/helper tests with `go test -race -count=10
./internal/codediagnostics`, full `go test -race ./...`, package lint (0 issues),
and Linux/Windows amd64 test cross-compilation pass. Helper tests cover ordinary
descendants, inherited blocked pipes after parent exit, output flooding and source
preservation on macOS. Full repository lint was run and reports 112 pre-existing
issues outside this package; unrelated files were not changed. Native Windows/
Linux runtime QA, hostile daemonization isolation and engine ownership wiring
remain later release-gate/integration work, not claims of this supervisor.

## Out of scope

Go/Svelte parsers, manager snapshots/result replacement, RPC/UI wiring, LSP stdio
transport, automatic checks, and broad platform QA (later release-gate tasks).
