- Status: 🟡 Partial (2026-10-22): spike, adapter seam and automated tests done; production route and manual draft QA not done

## Goal

Verify installed gopls versions, implement contained Go workspace detection and
push-diagnostic normalization, and prove draft freshness behavior. Re-estimate the
spike before committing support; APIs remain provisional until CD-01 is finalized.

## Current architecture and likely files

- Proposed `internal/codediagnostics/` gopls adapter and sanitized fixtures/tests.
- CD-19 session configuration/discovery and CD-21 document bridge integration tests.
- CD-05 Go checker module discovery may supply contained-root conventions.
- `go.mod` is a real local smoke-test root, not a reason to assume every host has gopls.
- Record supported versions/coverage in adapter documentation near the fixtures.

## Implementation steps

1. Probe explicitly installed versions using a bounded fixed executable/argv on
   an approved test project host; capture version, sync/encoding, and push behavior.
2. Commit sanitized initialize/publish/exit fixtures and a supported-version decision.
   If behavior cannot fit four hours, split follow-up work before implementation.
3. Detect go.mod/go.work and nested modules only inside the authorized root.
   Do not promote a selected subdirectory to a parent repository/workspace.
4. Define behavior for go.work entries outside the root, missing dependencies, and
   multi-module limits: report bounded partial/unavailable coverage, not extra access.
5. Resolve installed gopls with fixed argv and host environment conventions; absent
   or unsupported binaries produce independent provider availability status.
6. Configure one reusable root/server session through CD-19, advertise only supported
   capabilities, and open actual read-only/draft text through CD-21.
7. Normalize publishDiagnostics path, severity, source/code, optional range, and
   zero-based UTF-16 exclusive ends; preserve provider ownership and clear-on-empty.
8. Test whether supported versions include document versions in publications.
   Accept matching versions only; reject late/wrong-document snapshots.
9. For unversioned publications, invalidate ranges on edits and show uncertain results
   separately unless a specific synchronization strategy is tested and documented.
10. Declare opened-file versus broader server coverage, file-watch limitations, and
    failure states. Do not equate successful initialization or no findings with clean Go.

## Contract and security considerations

- Host-local execution applies equally to local, SSH, and WSL; no copied workspaces.
- Known-directory authorization and current CD-02 trust/fingerprint precede startup.
- gopls/toolchains may run project configuration, resolve dependencies, or write
  caches; approval is not a sandbox or an app-enforced no-network guarantee.
- Never install/download gopls or execute arbitrary package scripts/shell commands.
- Use CD-18 bounded transport and CD-19 safe configuration/request handlers; deny
  applyEdit, server commands, and unauthorized workspace expansion.
- Validate every diagnostic URI; out-of-root findings become provider status, not
  file links or an excuse to fetch out-of-root content.
- Keep bodies/raw protocol/results out of persistent logs; sanitize bounded errors.
- Baseline requires push; pull-only support is explicitly unsupported in this task.

## Focused tests and manual QA

- Fake fixtures cover initialization, opened saved/draft text, findings, empty clears,
  stale/wrong versions, unversioned pushes, crashes, and missing executable.
- Cover CRLF, non-BMP text, malformed ranges/URIs, nested modules, and out-of-root
  go.work entries without content disclosure or silent root widening.
- Run an approved installed-server smoke test: introduce/fix a Go type error in a
  draft and compare panel/inline state without saving or losing undo history.
- Confirm go vet and gopls attribution/coverage coexist without broad deduplication.

## Out of scope

Pull diagnostics, all gopls features, full Go lint coverage, completion, formatting,
quick fixes, automatic tool installation, and supporting every historical gopls version.
